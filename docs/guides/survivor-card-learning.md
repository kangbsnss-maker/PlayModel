# Brotato 전체 자동 플레이의 빌드 선택 학습

2026-09-27. 대상은 **Windows Steam Brotato 전체 자동 플레이**다. 이 문서는 캐릭터 선택·이동·결과·재시작에 연결되는 빌드 선택 부분을 다룬다. 사람 이동이나 카드 선택을 선행 조건으로 두지 않는다. 캐릭터 특성·강화·아이템·조합·슬롯 제한은 설치 빌드에서 확인한다. 실행·학습·평가는 로컬이며 GPT/API 토큰 서비스가 필요하지 않다.

## 현재 사용할 수 있는 기능

현재 CLI는 `doctor`, `validate-profile`, `brotato-inspect`, `brotato-capture`다. 실제 client 캡처를 확인했고 캐릭터 호버·로컬 중국어 OCR·시작 연결을 구현 중이다. 정책 학습·전체 자율 플레이는 아직 없다. 다음 명령은 환경과 Brotato 설정 초안을 확인한다.

```powershell
.venv/Scripts/python.exe -m playmodel doctor
.venv/Scripts/python.exe -m playmodel validate-profile configs/profiles/brotato.template.json --allow-draft
```

검사 성공은 게임 플레이 준비 완료가 아니다. `runtime_ready`는 현재 항상 `false`다. [실행 안내](../development.md)와 [카드 기록 예시](../examples/survivor-card-run.template.json)를 참고한다. 카드 기록 예시는 기록 항목을 설명하는 계약이며 `validate-profile`에 넣는 설정 파일이나 자동 수집 기능이 아니다.

## 전체 자동 실행에 연결할 기록

1. AI가 캐릭터를 호버해 특성과 잠금/해금 조건을 관찰하고, 선택한 캐릭터·시작 조건과 이동 정책 버전을 기록한다. 원문 판독과 의미 검증·가중치 학습은 분리한다.
2. 실행 중 **강화/상점 선택 직전 전체 후보**, **선택 직후 적용 결과**, **종료 결과**를 연결한다. 스탯·인벤토리 화면의 관측 시각도 보존한다. 자동 이동과 빌드 선택 모두 대상이다.
3. 처음에는 제안 화면 약 5–10회분으로 글자·위치·보유 목록·적용 확인 경로를 점검한다. 이는 계측 파일럿 제안이며 학습 충분성의 기준이 아니다. 실패·중도 종료도 남긴다.
4. 선택 이유를 남길 때 규칙/정책의 근거와 선택적인 사람 주석을 구분한다. “현재 효과와 결합 예상”, “생존 부족”, “슬롯 제약” 같은 설명을 검증된 시너지 정답으로 자동 취급하지 않는다.

원본 캡처·실제 입력·판독/보정 출처는 로컬 데이터 폴더에 보관한다. 사람 메모·시연은 선택적인 보조 자료다. 시간 정렬, 후보 ID, 적용 확인, 누락 표시를 검토하기 전에는 바로 학습 가능한 데이터라고 부르지 않는다. 한 판의 좋은 결과만으로 어떤 선택이 좋았는지 결론 내리지 않는다.

## 선택 하나에 필요한 기록

| 시점 | 보관할 내용 |
|---|---|
| 판 시작 | `run_id`, 게임/빌드/언어, 캐릭터·직업, 난이도, 영구 성장·해금 스냅샷, 이동 담당/정책 버전, 시드가 보이면 그 값 |
| 선택 직전 | 시간·웨이브·레벨·HP/최대 HP·재화, 보유 무기/아이템 전체와 각각의 레벨, 슬롯·조건·상태 효과, 상태를 확인한 시각과 캡처 참조 |
| 카드 제안 | `decision_id`, 후보별 의미 ID·화면 위치·문구·효과·희귀도·제약, 판독 신뢰/미확정 항목. 게임이 지원할 때만 reroll/skip과 남은 횟수·비용 |
| 선택·확인 | 고른 후보와 선택 출처(사람/정책), 정책·규칙 버전, 선택 확률을 실제 알 때만 그 값, 입력 시각, 적용 후 보유 목록/능력치·확인 화면 |
| 이후·종료 | 피해·사망·진행·보스/목표 달성 등 확인 가능한 사건, 종료 원인·생존 시간·게임이 제공한 결과 수치, 누락·연결 끊김·사람 개입 |

모르는 값은 `null` 또는 명시적인 unknown으로 남긴다. 사람 선택 확률을 임의로 만들어 쓰지 않는다. 클릭했다는 사실과 실제 업그레이드 적용은 별도다. 숫자 변화가 레벨, 장비, 일시 효과 중 무엇 때문인지 확인하지 못했다면 원인은 미확정이다.

선택 후 적은 이유는 회고 라벨이며 당시 정책 입력으로 쓰지 않는다. 적용 후 상태·후속 사건·최종 결과도 해당 선택의 입력에서 제외한다. 수동 영상으로 온라인 이용 가능 시각을 알 수 없으면 `available_at`을 만들어 채우지 않는다. 별도 메뉴에서 읽은 상태는 그 관찰 시각을 남겨 오래된 값이나 사후 정보를 구분한다.

## 어떤 모델을 만들 것인가

입력은 **현재 빌드·진행 상태와 이번에 나온 후보 집합**, 출력은 **현재 선택 가능한 후보의 점수·선택**이다. 첫 모델은 상태 인코더와 후보별 점수기를 갖는 작은 분류/순위 모델부터 비교한다. 카드 문구·검증된 효과 구조·보유 조합을 함께 사용하므로 고정 티어표보다 조건에 따른 선택을 표현할 수 있다. 실제 이득은 평가로 확인한다.

카드가 왼쪽에 있다는 것과 특정 효과라는 것을 구분한다. 의미 ID를 유지한 채 후보 순서를 바꿔도 같은 의미의 선택을 유지하는지 시험한다. 매 선택의 후보 수와 허용 mask를 사용하며, 나오지 않은 카드나 지원하지 않는 reroll을 출력하지 않는다. 미래에 나올 카드 목록은 모른다는 조건으로 판단한다.

가령 “현재 무기 A가 있을 때 B의 가치가 달라진다”는 관계는 게임 규칙 확인과 실제 결과로 학습·검증할 대상이다. 효과가 무조건 더해진다거나 특정 조합이 모든 상황에서 좋다고 가정하지 않는다. 보유 제한, 업그레이드 상한, 생존 압박, 남은 시간 때문에 같은 카드의 가치가 달라질 수 있다.

사람 자료가 있는 경우 BC로 선택을 모방하고 선택적으로 교정할 수 있다. 선택 일치율은 **최적 빌드 성능의 증거가 아니다.** 이전 행동이 이후 관측 분포를 바꾸는 문제는 [DAgger 원논문](https://proceedings.mlr.press/v15/ross11a.html)에서도 다룬다. 사람 자료가 없으면 명시된 규칙 기준선과 자율 시행·검증된 결과를 기반으로 학습 경로를 마련하며, 자기 출력을 자동 BC 정답으로 취급하지 않는다.

초기 카드가 이후 빌드와 선택 가능성을 바꿀 수 있으므로 매 선택을 독립적인 contextual bandit으로 보는 것은 제한적이다. 신뢰할 재시작·결과·충분한 반복 시행이 확보된 뒤 지연 보상을 다루는 순차 RL을 검토한다. 마지막 승리 점수를 모든 선택의 공헌으로 복사하지 않는다. 선택하지 않은 카드의 결과는 관찰되지 않았으므로 영상만으로 대안의 우열을 확정할 수도 없다.

## 빌드가 좋아졌는지 확인하는 방법

이동과 빌드 선택을 함께 바꾸면 개선 원인을 구분하기 어렵다. 빌드 비교에서는 같은 AI 이동 정책 버전을 사용하고, 빌드만 변경/이동만 변경/둘 다 변경을 나누어 본다. 선택적으로 받은 사람 시연은 다른 출처로 표시하고 자율 성과와 섞지 않는다.

훈련·평가는 **판 단위**로 분리한다. 같은 판의 앞 선택을 훈련, 뒤 선택을 시험에 나누면 빌드 이력이 겹친다. 캐릭터·영구 성장·난이도·이동 조건을 맞추고, 사용할 수 있다면 시드를 균형 있게 배정한다. 같은 시드도 선택 때문에 진행과 제안이 달라질 수 있다. 제시된 카드 운을 무시한 단일 최고 기록 비교는 피한다.

주요 결과는 실제 목표 달성·생존·진행과 게임이 제공하는 화력 지표 중 과제에 맞게 정한다. 후보 실행 전에 기준과 평가 배정을 고정하고, 고정 티어표/사람 시연 모방 등 기준선과 여러 판을 비교한다. 사망, 중단, 판독 실패를 숨기지 않는다. 카드 판독 정확도, 적용 확인 정확도, 최종 빌드 성과는 따로 보고한다.

## 앞으로 구현할 사용 흐름

예정 흐름은 **캐릭터 특성 확인·선택 → AI 이동·성장·상점 → 결과·재시작 → 검토된 자율 자료 → 로컬 학습·같은 조건 비교**다. 미해금 캐릭터 조건은 부목표로 추적하고 실제 해금 상태로 검증한다. 생존·진행 목표를 임의로 희생하거나 모든 스탯을 양수로 만드는 규칙을 쓰지 않는다. 이 전체 자동 흐름은 아직 완성되지 않았다. 세부 순서는 [Brotato 계획](../games/brotato.md)을 따른다.
