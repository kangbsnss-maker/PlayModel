# 다양한 빌드의 생존·성장 학습

2026-09-28 사용자 확정 목표: **다양한 캐릭터·무기·컨셉에서 적과 투사체를 피하고,
공격·성장 선택을 통해 오래 생존하는 플레이를 학습한다.** 단순 입력 횟수나 한 빌드의
생존 기록 최대화로 대체하지 않는다. 강화는 이후 생존에 기여하는 수단이다.

수집 요청은 초반부터 캐릭터·무기·컨셉을 교차하며 1,800개 요청 조합을 순환한다.
경유 중 잠긴 칸은 원래 목표를 바꾸지 않는다. 목표 자체가 잠긴 경우는 별도로 다룬다.
무기 후보는 캐릭터 특성 적합도로 정렬한 후 요청 순번을 선택한다. 요청 조합 수와
실제로 해금되어 플레이한 조합 수는 다르며, 컨셉은 달성된 빌드가 아닌 조건 의도다.

## 이번 구현

`screen_replay.py`는 완료된 학습 구간의 화면→실제 이동→다음 화면을 고정 자료로 만든다.
행동 원장 전체, 전송 영수증, 키 소유권, 프레임·메타데이터 해시, 독립 종료 증거를 검증한다.
같은 판의 여러 웨이브는 `run_id`별로 같은 train/validation/test 분리에 속한다.
평가판은 학습 자료에 넣지 않는다. AI가 했던 이동을 정답 BC 라벨로 쓰지 않는다.

`offline_survival.py`는 RGB 화면 2장→CNN→GRU와 시작 빌드 조건을 결합해 9개 이동의
Q값을 학습한다. DoubleDQN target과 discrete CQL 정규화를 사용한다.
캐릭터·시작 무기·컨셉·난이도·특성 원문을 고정 lexical hash 입력으로 보존한다.
이는 의미를 이해하는 사전학습 언어 모델이 아니며, 현재 인벤토리라고 해석하지 않는다.
빌드별 자료 수의 역수로 학습 손실을 가중해 흔한 빌드가 전체 목적을 독점하지 않게 한다.
소수 빌드의 과적합이나 미관측 빌드 성능을 해결했다고 주장하지 않는다.

자료는 반복 epoch로 재사용한다. 고유 전이 수·자료 방문 수·optimizer step·epoch를
별도로 기록하며 실제 완료 판수는 증가시키지 않는다. CPU thread 기본값은 2다.
인터넷·게임 실행 없이 학습할 수 있으나 컴퓨터 전원은 필요하다.

## 보상·종료 계약

- 정상 전송 뒤 다음 관측까지 확인된 전투시간 proxy만 보상한다. 현재 관측→전송 지연은
  포함되지 않아 실제 벽시계 생존시간과 다르다. 동일 프레임은 생존 보상 0이다.
- 제안값: 할인 시간척도 60초, 생존 보상 `60*(1-exp(-dt/60))`, 사망 -5,
  웨이브 완료 +1. 이동 횟수·구매 자체의 보상은 0이다. 최적값으로 검증된 수치가 아니다.
- 일반 관측 간격은 0.5초 이하. 입력 해제·권한 변경·불완전한 자료는 제외한다.
- 별도 정상 종료 연결: `phase-rejection` 원본에서 비전이 전투 관측을 거부하고,
  정상 `screen_changed`/`policy_abstained` 해제 전송을 마친 뒤 새 입력·권한 부여 없이
  같은 창의 독립 종료 관측이 5초 안에 도착해야 한다. 5초 역시 고정 설계 제안값이다.
  최초 변화 화면을 사망/완료로 소급 라벨링하지 않는다. 기다린 시간에는 생존 보상 0,
  종료 bootstrap 0. 해제 실행 구간과 종료 판독 지연을 따로 남긴다.
- 유효 종료 전이가 없는 구간 전체는 제외한다. 생존 보상만 남는 선택 편향을 방지한다.

후보는 **이동 후 화면 변화 시 키를 놓는 기존 실행기**를 전제로 한다. checkpoint에
`required_executor_schema`를 기록한다. 추후 평가도 이 계약을 따라야 한다.

## 실행

```text
python scripts/train_offline_survival.py freeze --session artifacts/laya-learning/SESSION --output artifacts/offline-survival/replay-NEW --max-segments 12
python scripts/train_offline_survival.py train --manifest artifacts/offline-survival/replay-NEW/manifest.json --output artifacts/offline-survival/candidate-NEW --epochs 8 --threads 2
```

매번 새 출력 폴더를 사용한다. 원본과 이전 후보를 덮어쓰지 않는다. 준비 환경에 PyTorch가
필요하다. 모델·자료는 Git에 넣지 않는다. 후보는 독립 schema로 저장되어 기존 Laya 자동
재개 후보가 아니다. 기존 모델로 초기화해 독립 자료가 섞이는 일을 피하도록 이번 기준선은
무작위 초기화다. 학습 report에 원본 manifest·코드 해시와 실제 파라미터 변화를 기록한다.

## 아직 충족하지 않은 전체 목표

이번 후보는 **시작 빌드 조건부 웨이브 내 이동 생존 학습**이다. 현재 능력치·현재 무기 구성,
상점 선택→강화→다음 웨이브 생존으로 이어지는 전체 판의 가치 학습은 포함하지 않는다.
기존 Laya의 상위 선택 학습과 절차형 메뉴 실행은 별도로 유지된다.
다음 통합에는 시간별 검증 인벤토리/능력치, 메뉴 행동과 다음 전투 결과를 잇는 상위 전이,
여러 웨이브를 연결한 반환이 필요하다. 모르는 스탯이나 무기 효과를 자동 정답으로 만들지 않는다.

실력 평가는 캐릭터×무기 계열×컨셉별 고정 평가판에서 생존시간·웨이브 진행·피격과
판정 가능한 공격/성장 결과를 비교해야 한다. 전체 평균만 좋아지고 특정 조합이 나빠지면
개선으로 숨기지 않는다. holdout 손실 감소·가중치 변경만으로 회피 능력 개선을 선언하거나
실제 actor를 자동 교체하지 않는다. 반복 학습은 새 경험을 만들지 않으며 실력의 기하급수적
향상도 보장하지 않는다. [CQL 원 논문](https://arxiv.org/abs/2006.04779).
