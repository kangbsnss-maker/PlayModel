# Laya 로컬 판단 학습

[동작 개념 HTML](laya-explained.html): 판단 흐름, 확률 실험, 로컬 실행 증거와 현재 한계.

`PlayModel.vbs` 실행 후 판단 모델을 `laya`로 선택하고 학습 시작.
성장·상점과 전투 전술은 Laya가 선택한다. 최신 화면의 CPU 기하 계산이 전술을 이동으로 바꾼다.
유효한 판단이 없을 때는 명시적 규칙 이동을 사용한다. 원본 영상·관측을 보존한다.
안전 중지 버튼/F8/`artifacts/BROTATO_STOP`는 기존과 같다.

프로그램의 **학습 도표 · 사람 전술 선호도 · 판단 근거** 버튼은 로컬 대시보드를 연다.
완료 판수와 진행 중인 판, 판단 수, 실제 제어 증거 수, 채택된 업데이트에 사용된 판단 수를
구분한다. 유효 학습 데이터는 실제 학습 manifest의 판단 ID를 중복 제거한 수치다.

사람은 전술별 선호도(logit bias, −2..2)와 수정 이유를 입력할 수 있다. 이 값은 신경망
head 텐서와 별도다. 값이 1이면 확률 100% 또는 2배라는 뜻이 아니다. 후보 전체의
`softmax(logits + bias)`에 상대적으로 작용한다. 현재 선택의 결과 학습이 끝난 안전
경계에서 적용되며 저장된 revision과 실제 적용된 revision을 따로 표시한다.
원래 확률·보정 후 확률·관측값을 근거로 보여준다. 이유 문장을 자동 해석하는 대화형
모델은 아니며, 사람의 메모를 보상이나 정답으로 자동 편입하지 않는다.

Laya 선택 → 메뉴 화면 적용 또는 전술 제어 증거 → 확인된 통과/사망 → 판단 head 학습 →
검사를 통과한 후보를 다음 선택에 사용한다. 선택이 없거나 미확인 결과면 업데이트하지 않는다.
학습 전후 행동 확률이 달라져도 생존 능력 향상을 입증한 것은 아니다.

Laya도 신경망 가중치로 선택한다. 현재는 encoder를 고정하고 판단 head만 갱신한다.
전투 중 Laya 판단 추론과 CPU 이동은 비동기로 진행한다. 실제 결과가 확인된 전투 경계에서
학습하며, 전투 도중 Laya optimizer까지 동시에 실행하는 구조는 아니다. 선택형 모델이라는
공통점만으로 Jev와 같은 모델·성능으로 간주하지 않는다. 외부 판단 API·토큰 종량 과금은 없다.
내부 텍스트 토큰 처리와 로컬 GPU·메모리·전력 사용은 있다.

제한 복구가 발생한 전투는 앞선 선택의 보상으로 사용하지 않는다. 그 선택 기록은
보존하고 학습 대상에서 제외하며, 전술 추적 상태를 초기화한 뒤 다음 정상 구간에서 다시 수집한다.

입력 해제가 증명된 화면 전환은 관측 대기로 넘긴다. 일시정지·미확인 화면에서는
키를 보내지 않고 관측 기록을 계속 저장한다. 일시정지 해제 뒤 동일 대상의 최신 화면
두 개가 일치하면 정상 수집으로 돌아간다. 불확실한 구간은 보상 학습에 넣지 않는다.
사용자 중지/F8, 대상 불일치, 불확실한 부분 전송, 입력 해제 실패는 계속 중단한다.

전술 후보는 접근·후퇴·거리 유지·선회·거리 두며 이동·교차 회피를 상황별로 구성한다.
근접/원거리 피해량·속도·방어·회피·재생·공격 속도 관측을 사용한다. 적/투사체 정체·실제
무기 사거리·현재 숫자 HP·정확한 공격 주기는 아직 unknown이다. [설계와 한계](../decisions/0011-laya-combat-tactics.md).

## 설치와 실행

기존 `.venv`의 GPU 환경을 먼저 준비한다. `scripts/setup_laya_environment.ps1`은
별도 `.venv-laya`에 고정 라이브러리를 설치하고 영어 모델을 `models/laya/base`에 받는다.
모델은 `convaiinnovations/laya@55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`로 고정한다.
출처·파일 해시는 `source-manifest.json`에 기록된다. 실행 worker는 offline 설정을 강제한다.

직접 진입점: `scripts/run_laya_learning.py <고정 CNN 체크포인트.pt> --model-dir models/laya/base --continuous --recover-active-run`.
Python은 기존 `.venv/Scripts/python.exe`로 실행한다. Laya worker만 별도 환경을 쓴다.
Windows 보조 프로세스는 숨김 실행한다. 기존 stop 파일이 있으면 명시적 시작 버튼으로 재개한다.

백그라운드 실행 전 게임 메인 메뉴의 **Options → Sound → On losing focus**를
**Do nothing**으로 설정한다. **Pause**면 다른 창으로 이동할 때 게임 자체가
일시정지한다. 이 옵션은 플레이 중 옵션 화면에 나타나지 않는다. 앱은 저장된
설정을 읽어 켜짐 여부와 변경 경로를 표시하며 설정 파일을 자동 수정하지 않는다.

사용자 제공 아이콘은 앱 제목 표시줄에 적용된다. Windows에서는
`scripts/create_app_shortcut.ps1`로 같은 아이콘의 `PlayModel.lnk`를 만든다.

`scripts/probe_laya.py`는 합성 자료로 실제 모델 forward/gradient/저장/재로딩을 검사한다.
이 결과는 게임 학습이 아니며 기본 재개 후보 검색에서도 제외한다.

## 증거

로컬 앱 상단에서 누적 판단 수, 채택된 가중치 갱신 횟수, 실제 학습에 사용된
유효 판단 자료 수, 완료 학습 판수를 바로 확인한다. 약 3초마다 별도 스레드에서
기록을 집계하며 브라우저를 열 필요가 없다. 조회 오류는 마지막 확인값을 유지하고
재시도한다. 판단 횟수와 가중치 갱신 횟수는 서로 다른 수치다.

- `artifacts/laya-learning/<실행>/status.json`: 실제 실행 상태.
- `laya-state.json`: 실행 경로·복구용 CNN·업데이트 기록.
- `laya/choice-*.json`: 상황·선택지·토큰·실제 샘플·분포·모델 버전.
- `laya/accepted-*.json`: 메뉴 화면 적용 또는 별도 전술 제어 증거. 전술은 화면 반영 검증과 구별한다.
- `laya/update-*/dataset-manifest.json`: 학습 전 고정한 자료·결과 해시.
- `laya/update-*/report.json`: optimizer, head/encoder 해시, KL, 후보 채택 여부.
- `laya/update-*/head.pt`: 판단 head 후보. 원본 encoder는 별도 고정 파일을 참조.

속도는 전체 화면→입력과 Laya 연산 시간을 따로 본다. 비동기화로 모델 대기는 이동 경로에서
분리했지만, 실제 속도·생존 향상은 별도 측정해야 한다.

소지 무기 관측은 첫 줄 1–3개 배치에서 취소·재활용·표시된 합성을 별도 선택으로 수집한다.
판매액·대상 제거·잔여 재고가 맞아야 채택하며, 합성의 실제 등급 상승은 미검증이다.
계열/세트 문구는 원본과 저장하고 구매 문맥에 전달한다. 모든 계열 효과를 해석했다고 보지 않는다.
미전송 탐색 실패와 정상 상점으로 복귀한 결과 불명 선택은 해당 선택만 제외하고 진행한다.
사용자 중지·게임 종료·입력 소유권 실패까지 무시하는 무중단 실행은 제공하지 않는다.
