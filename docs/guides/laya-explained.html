Laya와 Jev는 정해진 선택 형식으로 답한다는 공통점이 있습니다. 같은 모델·구현·성능이라는 뜻은 아닙니다.

같은 방향을 반복하는 대신, 관측 상태로 후보를 만들고 Laya가 고릅니다. 아래는 구현한 전술의 개념 설명이며 실제 게임 화면이나 학습 성적이 아닙니다.

접근하는 위험 후보

상대 속도와 가장 가까워질 위치를 추정합니다. 뒤로 빠지기·좌우 선회·접근 경로 벗어나기가 후보가 됩니다. 작고 빠른 물체도 추적하지만 미사일이라고 확정하지 않습니다.

가까이 공격할지, 거리 둘지

관측한 근접·원거리 피해량, 속도, 방어, 회피, 재생, 공격 속도로 거리 선호를 조정합니다. 접근·거리 유지·거리를 벌리며 이동 같은 후보가 달라집니다.

움직임 패턴 변화

여러 화면에서 접근·교차·선회 가설을 갱신합니다. 좌표만 달라져도 이동 방향은 다시 계산합니다. 후보 전체의 의미가 바뀌면 이전 Laya 응답을 버립니다.

관측의 한계

몬스터 종류·발사 주체·공격 주기·실제 무기 사거리·현재 숫자 HP는 아직 확정 인식하지 못합니다. 화면 거리와 Range 능력치를 같은 단위로 취급하지 않습니다. 정확한 공격 패턴 학습에는 검증된 탐지 자료가 더 필요합니다.

최신 화면 → 추적·후보→별도 Laya 추론→유효한 전술만 채택→최신 화면으로 이동 계산

유효한 새 판단이 없으면 명시적인 규칙 이동을 사용합니다. 후보·모델 버전·전투 식별자·시간 제한을 함께 검사합니다. 기본 750ms 요청 간격과 1.5초 유효기간은 초기 설정이며 최적값으로 측정된 수치가 아닙니다.

2026년 9월 27일 후속 실행에서 실제 전술 제어 → 독립 전투 결과 → head 갱신 → 새 버전 제어를 확인했습니다. 사람 선호도 revision의 안전 경계 적용도 확인했습니다. 최신 누적 수치는 프로그램의 학습 도표에서 봅니다. 생존 능력 향상은 아직 입증하지 않았습니다.

한 번의 선택이 다음 선택을 바꾸는 과정

모델은 화면을 직접 조작하지 않습니다. 프로그램이 관측과 후보를 준비하고, 입력 전후의 검증을 담당합니다.

  1. 화면 캡처 · 로컬 OCR화면·텍스트·관측 시각을 보존합니다. 읽지 못한 값은 unknown으로 남깁니다.
  2. 상황 + 유효한 선택지관측한 능력치·보유 무기·재화와 현재 선택 가능한 후보만 묶습니다.
  3. ModernBERT encoder텍스트를 신경망 표현으로 바꿉니다. 현재 실험에서는 이 가중치를 고정합니다.
  4. 판단 head → 선택 확률후보별 확률을 계산하고 실제로 하나를 표본추출합니다. 선택과 모델 버전을 기록합니다.
  5. 실제 제어 증거메뉴는 화면 반영까지 검사합니다. 전술은 실제 키 전송 또는 이미 보유한 키 유지 증거를 남깁니다. 이를 게임 반영 확인으로 부풀리지 않습니다.
  6. 독립적으로 확인한 결과다음 전투의 wave_clear는 +1, death는 −1. 클릭 성공 자체에는 좋은 선택 보상을 주지 않습니다.
  7. Head REINFORCE 학습실제 선택 확률과 시간 할인한 결과로 판단 가중치를 갱신합니다. 자기 선택을 정답으로 복사하지 않습니다.
  8. 검사 → 저장 → 다음 선택확률 변화·수치·encoder 불변·재로딩을 검사합니다. 통과한 새 버전을 다음 선택에 사용합니다.

08 → 01 · 새 상황을 다시 관측하고, 갱신한 head로 다음 후보를 고릅니다.

전투 이동→전투 결과 확인→대기하며 Laya 학습→다음 메뉴 선택

전투 중 Laya 판단 추론과 CPU 이동은 비동기로 진행합니다. 가중치 학습은 독립적으로 확인한 전투 결과 뒤에 진행합니다. optimizer까지 전투와 동시에 실행하는 구조는 아닙니다.

어떤 기록은 학습에서 제외하나요?

미확인 입력·적용 실패·사용자 중지·알 수 없는 결과를 정답이나 사망 보상으로 쓰지 않습니다. 제한 복구로 전투가 끊기면 앞선 메뉴 선택을 그 전투 결과로 학습하지 않고 원본 기록을 보존합니다.

이 실험의 자료는 학습용입니다. Laya가 개입한 기록은 CNN PPO와 독립 평가 점수에서 제외합니다.

사람이 판단을 교정하고, 근거를 남깁니다.

프로그램의 학습 도표 · 사람 전술 선호도 · 판단 근거 버튼에서 실제 기록을 봅니다. 완료 판수·진행 중인 판·판단 수·실제 제어 수·학습에 사용된 판단 수를 구분합니다.

수정하는 값

접근·후퇴·선회 같은 전술별 선호도(logit bias)를 −2부터 2까지 조절합니다. 신경망 head 가중치는 별도로 보존합니다. 수정 이유와 연결한 판단 기록도 남깁니다.

실제 선택 분포 = softmax(신경망 점수 + 사람 선호도)

선호도는 확률이나 배율이 아닙니다. 값이 1이라고 확률 100%나 2배를 뜻하지 않습니다.

적용되는 시점

저장된 교정은 대기 상태입니다. 현재 선택의 결과 학습을 마친 안전 경계에서 적용하고, 실제 사용된 설정과 모델 버전을 함께 남깁니다.

화면에는 관측값·기본 확률·보정 후 확률을 보여줍니다. 모델 내부 사고를 읽은 설명은 아닙니다. 사람의 이유 문장은 기록으로 보존하며 자동 보상·정답으로 사용하지 않습니다.

보상이 선택 확률에 미치는 영향

아래는 원리를 보여주는 작은 실험입니다. 실제 Laya 모델이나 Brotato를 실행하지 않습니다.

가상 수치 · 교육용 계산 · 게임 실측 아님

가상의 상점에서 선택을 하나 뽑고, 그 뒤에 관측됐다고 가정할 결과를 눌러 보세요.

  • 재화를 남기고 출발25.0%
가상 head · v0

먼저 선택을 뽑으세요. 높은 확률의 후보도 매번 뽑히는 것은 아닙니다.

확률은 행동 선호도입니다. 생존 성공 확률이 아닙니다. 한 번의 결과로 선택이 옳거나 틀렸다고 확정할 수도 없습니다.

이 실험의 계산과 실제 학습은 어떻게 다른가요?

이 페이지는 후보별 점수 세 개를 softmax로 확률로 바꾸고, 선택한 행동의 log 확률에 보상을 곱하는 방향으로 점수를 한 번 움직입니다. 양의 보상은 선택한 후보의 확률을 높이고 음의 보상은 낮춥니다.

가상 점수 변화 = 0.45 × 보상 × (선택 여부 − 현재 확률)

0.45는 변화를 보기 쉽게 정한 교육용 수치입니다. 실제 프로그램은 Laya head의 다수 가중치에 역전파·시간 할인·Adam·기울기 제한·확률 변화 검사를 적용합니다. 이 페이지의 변화량을 실제 학습 속도나 성능으로 해석하면 안 됩니다.

실게임 학습과 새 버전 적용 확인

최초 업데이트는 실제 적용한 선택 3개와 독립 확인한 사망 결과를 사용했습니다. Head 변경·encoder 불변·저장·재로딩을 통과했고, 새 버전 선택 1회가 게임에 적용됐습니다.

선택 확률이 바뀌었다는 증거입니다. 더 잘 생존하거나 빠르게 이동한다는 뜻은 아닙니다. 복구 공백의 선택은 기록을 보존하고 학습에서 제외하므로 선택 수와 학습 자료 수가 다를 수 있습니다.

확인 순서: 실제 선택 → 실제 적용 → 독립 결과 → head 갱신 → 새 버전의 실제 선택. 이동 속도·생존 능력 향상과 전체 자동 플레이 완료는 아직 입증되지 않았습니다.
