# 로컬 신경망 학습 — 현재 구현과 실제 측정

2026-09-27. 채택 구조: 공유 CNN + GRU + 단계별 선택 출력 + PPO. 실행 중 GPT/API나 개발 에이전트는 필요하지 않는다. 아래 명령은 로컬 Python 프로그램이다. 다만 무인 전체 판 반복과 강화·회피 학습까지 모두 검증된 상태는 아니다.

## 목표

적 접촉·적 투사체를 피하고, 자원 수집·성장·상점·환경 상호작용으로 강해지는 방법을 배운다. 한 웨이브가 아니라 캐릭터 선택부터 최종 결과까지를 한 판으로 취급한다. 구매·성장 선택의 성공과 이후 전투에 도움이 되었는지는 별도다.

현재 실제 전투 보상은 독립 판독한 웨이브 종료와 사망이다. 접촉/투사체별 회피, 나무의 보상, 상점 선택의 장기 이득을 이미 습득했다는 증거는 없다. HP 감소의 원인을 확인하지 못하면 원인은 `unknown`이다.

## 플레이와 별도 학습 작업자

`PlayModel.vbs`의 시작 경로는 반복 실행 조정자를 실행한다. 완성된 학습판의 자료를 고정한 뒤 별도 숨김 PPO 작업자를 준비하고, 게임 쪽은 고정 원본 모델의 평가판을 진행한다. 해당 평가판의 첫 실제 이동 입력이 기록된 뒤 PPO 최적화를 시작한다. 평가판이 끝나면 후보 저장·재로딩·수치 검증 결과를 확인하고 후보 평가판으로 넘어간다. 이후 새 학습판을 수집해 반복한다. 실행 중 GPT/API 토큰은 필요하지 않다.

같은 자료를 끝없이 다시 학습하지 않는다. 각 PPO 갱신은 제한된 epoch와 KL 중단을 적용한다. 평가 자료는 해당 갱신에 넣지 않는다. 기존에 저장된 후보가 있으면 재개 시 복원하므로, 시작 직후부터 매번 새 학습 프로세스가 생기는 것은 아니다.

학습 작업 기록은 세션 폴더 아래 `training-jobs`에, 실행 로그는 `artifacts/program-logs`에 남는다. 실제 가중치 갱신과 게임 입력의 시간 중첩은 기록으로 확인한다. 프로세스가 둘 있다는 사실만으로 전투와 학습이 실제로 겹쳤다고 판정하지 않는다. 학습 실패 시 미검증 후보를 사용하지 않는다. [저장·중단·재개 계약](../decisions/0008-background-recurrent-training.md).

## 제한된 하드웨어에서 자료 재사용

- 실제 장비: Ryzen 5 3600XT, RAM 약 32GB, GTX 1660 SUPER 6GB. PyTorch 2.7.1+cu126의 실제 GPU 연산을 확인했다.
- 신경망은 789,334개 파라미터이며 진단용 재구성 디코더를 포함한다. 행동 입력은 96×96 RGB, GRU 기억은 128차원이다. 글자·능력치 판독은 원본 해상도를 별도로 쓴다.
  이 수치는 최초 context16 모델 기준이다. 스탯 입력 확장 모델은 context64이며 GRU 입력 가중치 18,432개를 추가한다.
- 기존 화면은 시각 인코더의 자기지도 학습에 재사용한다. 과거 AI 행동을 정답으로 복제하지 않는다. 새 PPO는 해당 정책이 실제 실행한 관측·행동 확률·결과를 사용한다.
- 같은 자료의 PPO 재사용은 제한된 epoch와 KL 검사 안에서 진행한다. 가중치가 바뀌면 새 경험을 수집한다. 원본 자료는 보존한다.
- 학습/평가는 전체 판 단위로 분리한다. 화면을 CPU에서 필요한 만큼 읽고 작은 배치만 GPU로 보낸다. 짧은 재귀 학습 구간을 쓰더라도 보상 계산은 전체 시간순 기록에서 수행한다.

## 실행 경로

저장소 루트, 학습 의존성을 설치한 `.venv` 기준. Windows에서는 프로젝트의 숨김 실행 도구로 Python을 호출한다.

```text
python scripts/train_recurrent_model.py MANIFEST OUTPUT_DIR --steps 200 --batch-size 16 --device cuda
python scripts/run_recurrent_trial.py CHECKPOINT --waves 1 --seconds 180
python scripts/train_recurrent_rollout.py CHECKPOINT ROLLOUT OUTPUT_DIR --device cuda --epochs 4
```

첫 명령은 과거 화면 학습, 둘째는 OBS 녹화를 포함한 제한된 실제 신경망 전투 수집, 셋째는 별도 학습이다. 둘째 명령의 메뉴 선택은 현재 명시된 초기 규칙이다. 성장·상점 신경망 선택 어댑터와 전체 판 기록기는 별도로 구현하며, 연결 전에는 이 명령이 전부를 학습한다고 설명하지 않는다. F8 또는 `artifacts/BROTATO_STOP`으로 입력을 중단한다.

## 무인 반복의 완료 기준

하나의 로컬 실행기가 판 시작→전투·성장·상점→최종 결과→자료 확정→학습→독립 평가를 연결해야 한다. 모델은 판 도중 바꾸지 않는다. 실패한 인식·입력은 근거를 남기고 제한된 재관찰 후 중단한다. 평가 통과 후보만 기본 모델로 승격한다. 이 전체 경로의 실게임 검증과 접촉·투사체·강화별 평가가 남아 있다.

## 에이전트 없는 연속 실행기

수동 실행 창은 루트의 `PlayModel.vbs`로 연다. [독립 실행 가이드](standalone-learning.html)에 시작·중지·상태 복원·진단 위치를 정리했다. 창과 학습 프로세스는 분리돼 있으며, 창을 닫거나 개발 대화가 끝나도 정상 학습은 계속된다.

`scripts/run_recurrent_cycle.py`에 로컬 수집·학습·새 판 비교를 연결했다. `--continuous`는 비교를 마친 실험 후보로 다음 학습 사이클을 진행한다. 기본 배포 모델 승격과는 다르며 자동 승인하지 않는다. 캐릭터·시작 무기 선택은 아직 초기 규칙이다. 성장·지원되는 상점 구매·출발 선택은 전투와 같은 신경망과 판 기억을 사용한다. 미지원 보상 화면은 임의 규칙으로 대체하지 않고 중단한다.

```text
python scripts/run_recurrent_cycle.py CHECKPOINT --continuous --evaluation-runs 1 --max-run-seconds 1800 --device cuda
```

현재 새 사이클은 확인된 사망/결과 화면에서 시작한다. 진행 중 판을 임의로 초기화하지 않는다. 한 판의 시간 예산이 끝나면 `budget_paused`, 사용자 중지는 `user_stopped`, 오류는 `fault_paused`로 구분한다. F8 또는 `artifacts/BROTATO_STOP`이 중지 신호다. 중지 파일은 자동 삭제하지 않는다.

수동 실행 창은 `--resume-latest --recover-active-run`을 사용한다. 저장된 `session-state.json`에서 완료한 수집·학습·평가 단계를 재사용한다. 초기 비교 복원에는 `--resume-summary`로 기존 기록을 지정할 수 있다. 진행 중인 판의 복구 기록은 중간 진입임을 표시하고 정식 학습·평가에서 제외한다. 시작 버튼은 명시적인 재개 요청이므로 중지 파일을 해제하지만, 프로그램의 자동 복구는 중지 파일을 지우지 않는다.

실행 폴더의 `status.json`은 단계와 프로세스 생존 시각을 기록한다. 생존 신호와 실제 게임 진행 시각은 별도다. 오류는 `help-request.json`과 원본 자료를 남긴다. 자동 GPT 호출은 없고, 오류 난 프로그램을 끝없이 재시작하지 않는다. 개발 에이전트는 오류 분석·수정·재검증·명시적 재시작 때만 사용한다. 정상 학습이 외부 API 토큰을 소비하지 않는 구조이며, 이 개발 대화의 토큰 사용과는 별개다.

`help-request.json`은 최신 오류를 가리킨다. 이전 요청은 같은 폴더의 `help-requests/`에 보존한다. 이어하기 중 새 오류가 나면 이전 실행의 오류 문구를 재사용하지 않는다.

상점 잔액의 한 자리 숫자를 기본 OCR이 놓치거나 `00`처럼 모호한 선행 0 결과를 내면 원본 숫자 영역을 복제한 로컬 OCR 입력으로 재관찰한다. 복제본을 독립 관측으로 세지 않는다. 서로 다른 실제 프레임의 일치와 구매 전후 가격·상품·재고 변화를 검증한다. 원본 및 파생 이미지·OCR 해시를 학습 기록에 묶어 보존한다. 실게임 실패 원본의 잔액 29→1 및 92→64 구매 검증을 통과했다. 이 결과는 인식·구매 검증이며 정책 실력 향상 증거는 아니다.

전투 입력에는 25ms 전송 제한이 있다. 텐서 변환·직렬화용 값 준비는 정책 작업자가 수행하며 입력 전송 경로와 분리한다. 실제 전송 시작·완료와 실패 시 전송 여부 불확실성을 별도 보존한다. 시간 제한 위반은 키 해제 후 학습 제외로 처리한다. 드문 시스템 지연이 완전히 제거됐다는 의미는 아니다.

## 현재 스탯과 보유 무기 입력

`brotato-observed-build-v2`는 기존 문맥 16개 뒤에 표시 주스탯 값 16개, 확인 마스크 16개, 보유 무기 이름의 lexical sketch 8개, 상태·관측 경과 시간 8개를 연결한다. 메뉴와 전투가 같은 상태를 사용한다. 마지막으로 읽은 스탯이며 전투 중 현재 HP·임시 버프·피해 원인을 보장하는 정보는 아니다.

스탯 영역을 2배 확대해 기존 로컬 OCR로 읽는다. 두 독립 프레임에서 값이 합의된 항목만 사용한다. 숫자 누락·부호 불명·모호한 값은 unknown이다. 원본 PNG, 파생 이미지·OCR, 관측·이용 가능 시각, 해시를 기록한다. 실제 보존 상점 두 프레임은 각각 16/16, 레벨업 두 프레임은 16/16 및 15/16을 판독했다. 인식 정확도 전체를 보장하는 평가 결과는 아니다.

무기 이름은 검증된 초기 선택과 실제 구매 적용 기록으로만 누적한다. 수량이나 보유품 변화가 설명되지 않으면 불완전한 정보를 명시한다. 이름으로 능력치 효과를 임의 추정하지 않는다. 성장·구매 뒤에는 스탯을 다시 관측한다. 구매·리롤 자체의 즉시 보상은 0이며, 이후 검증된 전투 결과로 같은 전체 판 궤적에서 학습한다. 처치·경험치·접촉 및 투사체 피해별 독립 보상은 아직 연결하지 않았다.

`models/recurrent/20260927-build-v2/warmstart.pt`는 679개 전이로 갱신한 후보의 기존 가중치를 보존하고 추가 문맥 열만 0으로 초기화한 별도 모델이다. 변환 자체는 학습이 아니다. 새 입력의 영향을 학습하려면 새 판 수집과 PPO 갱신이 필요하다. 기존 체크포인트·학습 자료·미완료 비교 상태를 덮어쓰지 않으며, 이전 rollout은 새 모델의 PPO에 재사용하지 않는다.
