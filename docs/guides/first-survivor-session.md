# Brotato 현재 실행 안내

대상은 **Windows Steam Brotato 전체 자동 플레이**다. AI가 캐릭터 선택부터 이동·성장·상점·결과·다음 판을 담당한다. 사람이 먼저 플레이하거나 JSON을 작성해야 하는 흐름이 아니다. 현재는 설치 진단과 실제 1920×1080 client 캡처를 확인했으며, 전체 자율 플레이와 정책 학습은 아직 구현되지 않았다.

## 지금 실행 가능한 것

```powershell
.venv/Scripts/python.exe -m playmodel doctor
.venv/Scripts/python.exe -m playmodel brotato-inspect
.venv/Scripts/python.exe -m playmodel validate-profile configs/profiles/brotato.template.json --allow-draft
.venv/Scripts/python.exe -m playmodel brotato-capture
```

마지막 명령은 실행 중인 Brotato의 client 한 장과 manifest를 `data/raw/brotato-observations`에 저장한다. 클릭·키 입력·학습을 수행하지 않는다. 자료는 검토 대기이며 `usable_for_training: false`다. [개발 안내](../development.md)에 설치와 오류 구분을 정리했다.

## 현재 연결 중인 캐릭터 관찰

중국어 캐릭터 선택 화면에서 **호버 → 특성/잠금 조건 캡처 → 로컬 OCR → 근거가 있는 지식 기록 → 선택·게임 시작 확인**을 연결한다. 로컬 OCR 언어팩 `zh-Hans-CN`은 확인했지만 언어팩 존재가 특성의 정확한 해석을 보장하지 않는다. 화면을 읽어 저장하는 것과 정책 가중치를 학습하는 것은 구분한다. 개발자가 판독·메뉴 위치를 보정했다면 그 출처를 남긴다.

미해금 캐릭터는 부목표로 다룬다. 조건 원문을 확인하고 수량·비교·기간·난이도를 해석한 뒤 실행 중 진행을 기록한다. 조건을 달성했다고 추정하는 것만으로 해금 완료를 선언하지 않으며, 알림이나 실제 선택 가능 상태를 확인한다. 주목표인 생존·진행을 임의로 희생하지 않는다.

## 실행에서 자동으로 남길 기록

| 장면 | 기록할 것 |
|---|---|
| 시작 | 게임/버전, 캐릭터, 스테이지/난이도, 영구 성장·해금, 시작 장비 |
| 캐릭터 호버 | 대상 셀/식별 근거, 원문·특성·잠금/해금 조건, 캡처·관측/가용 시각, 추출·보정 출처 |
| 선택 직전 | 게임 시간/레벨, 현재 보유 카드·무기·강화 단계, 필요하면 체력·재화, 후보 전체 화면 |
| 선택 | 실제 고른 후보·화면 위치, 정책/규칙 버전, 판단 근거를 기록한 시점 |
| 선택 직후 | 보유 목록/강화 단계가 바뀐 증거, 적용 실패·취소 여부 |
| 종료 | 생존 시간, 목표 달성·실패·중단, 최종 빌드, 제공되는 전투 결과 |

모르는 숫자나 규칙은 추측해서 채우지 않는다. 현재 문구와 실제 적용 결과가 다른지 확인하는 것도 첫 기록의 목적이다. 카드가 선택되었다고 추정한 클릭과 실제 적용 확인을 구분한다.

영상의 위치와 게임 안의 경과 시간은 별도로 적는다. 수동 녹화만으로 모델의 정보 이용 가능 시각을 알 수 없으면 `available_at`은 미확정으로 남긴다. 빌드/스탯 화면을 언제 찍었는지도 필요하다. 선택 이후에 찍은 화면을 선택 전 상태로 쓰면 안 된다. 선택 이유는 회고 주석이며, 기록 시점을 함께 남기고 기본 정책 입력에서 제외한다. 선택 후 적용 상태·후속 사건·최종 승패 역시 해당 선택 시점의 입력으로 넣지 않는다.

## 선택적인 진단·교정 자료

```text
data/raw/optional-demonstrations/run-001/
  start.png
  level-02-offer.png
  level-02-applied.png
  notes.md
  result.png
  recording.mkv
```

필요할 때 사람이 추가 화면·시연·교정을 제공할 수 있다. 제품의 필수 시작 절차는 아니다. 위 경로는 예시이며 실제로 수집하지 않은 장면을 만들어 채우지 않는다. `data/`는 Git 제외다. 파일명의 레벨은 게임의 첫 선택 시점을 단정하지 않는다.

개발자가 사용할 상세 [기록 계약 예시](../examples/survivor-card-run.template.json)도 제공한다. **현재 CLI의 게임 프로필이 아니므로 `validate-profile`에 넣지 않는다.** 이 JSON을 만들었다고 자동 수집·데이터 검증·학습이 수행되지는 않는다. 실제 기록은 원본 참조·시간·버전과 함께 검증한 뒤 별도 데이터셋으로 승격한다. 사용자가 처음부터 JSON을 손으로 모두 채울 필요는 없다.

## 앞으로 만들 사용 흐름

게임 연결 → 캐릭터 특성·해금 조건 확인 → AI 캐릭터/시작 조건 선택 → AI 이동·성장·상점 → 결과·정상 재시작 → 검증된 자율 자료로 로컬 학습·고정 비교.

이 전체 흐름은 **개발 중인 목표**다. 초기 규칙 정책과 학습된 정책을 구분한다. 빌드 정책만 비교할 때는 AI 이동 정책 버전을 고정하고, 이동과 빌드를 함께 바꾼 통합 성과도 따로 평가한다. 사람의 대리 조작을 자율 성공으로 세지 않는다.

학습 목표·조건·검증 기준은 [카드 성장 학습 설계](survivor-card-learning.md)를 따른다. 현재 선택 한 번이 다음 후보·진화 가능성·생존에 영향을 주므로 단순 카드 등급표나 마지막 승패 하나로 모든 선택의 좋고 나쁨을 확정하지 않는다.
