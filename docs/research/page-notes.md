## page-04

**02 전체 시스템과 모델의 경계**

- 실행: 화면 → 관측 정렬/전처리 → CNN·GRU → AI 제안. 사람 입력과 AI 제안 → 조작권 관리자 → 단일 최종 전송 → 게임.
- 개선: 영상/입력/개입/결과 → 품질 검사 → 고정 데이터셋 → BC/교정 학습 → 후보 → 별도 평가 → 승인 → 다음 에피소드 적용.
- 관측 모듈은 화면 식별·지연·누락을 관리하고 미래 화면을 현재 정답에 붙이지 않는다. 정책은 시각 특징·기억·행동 분포만 담당하고 메뉴·리셋·조작권을 임의로 바꾸지 않는다.
- 조작권 관리자는 사람 우선 인수와 최종 입력 단일화를 맡는다. 사람과 AI의 버튼 상태를 무조건 합치지 않는다. 기록 관리자는 사용 중 학습 자료를 자동 삭제하지 않는다. 학습 관리자는 운영 중 가중치를 덮어쓰지 않는다.
- 최소 계약: 관측은 화면/관측 시각/직전 전송 입력/품질, 정책은 분포/선택 입력/새 기억, 연결부는 전송 결과/다음 관측/종료 상태를 제공한다. 초기 BC에 보상이 없어도 경계는 유지한다.
- 기록은 사건 보존, 검색은 과거 사건 조회, 학습은 가중치 변경이다. 시뮬레이터와 실제 콘솔은 공통 계약 뒤의 별도 연결부다.

## page-05

**03 관측 입력과 정보 접근**

- 원안 입력: 비율을 보존한 RGB 320×180, 최근 **4개 판단 시점**의 특징, 직전 최종 전송 버튼/축, 실제 시간 간격·관측 나이·이력 유효성, 이전 GRU 상태. 크기는 저장 원본 해상도와 다르다.
- 미래 성공/실패, 나중 사람 개입 여부, 화면에 없는 내부 상태는 첫 화면 정책의 입력에서 제외한다. 허용된 내부 상태를 보상/진단에 쓰면 별도 경로임을 표시한다.
- 사람/AI 주체·교정 여부는 출처와 학습 마스크에 저장하지만 첫 정책의 입력 특징으로 넣지 않는다.
- 판단 시각 `d_t`에서 이용 가능한 최신 유효 화면을 `o_t`로 선택한다. 입력 이력에는 `d_t` 전에 전송한 값만 넣는다. 예측 정답 `a_t`를 같은 시점 입력에 넣지 않는다.
- 실제 입력의 기본 뜻은 중재 후 **장치에 최종 전송한 값**이다. 장치 수신 및 게임 내 적용 여부는 서로 다른 사건이며 확인 불가를 성공으로 채우지 않는다.
- 시연도 사람이 실제 볼 수 있었던 화면과 정렬해야 한다. 오디오/음성은 초기 모델에서 제외하므로 소리만으로 판정해야 하는 게임에서는 관측 규격을 다시 정해야 한다.

## page-06

**04 시각 인코더 설계**

- ResNet-18급 CNN을 기준선 후보로 제안한다. ImageNet 사전학습은 게임 행동 학습이 아니며 사전학습 사용 여부/추가 학습 범위는 비교 대상이다. R04.
- 원안 형상: 입력 `[3,180,320]` → 표준 stride32의 합성곱 특징 `[512,6,10]` → 3×5 공간 격자 풀링 → `512×3×5=7,680` → 선형층/활성화 256차원 → 최근 4시점 연결 `256×4=1,024`차원.
- 전역 평균 하나로 즉시 줄이지 않고 공간 배열을 보존하려는 제안이다. 실제 백본·패딩·전처리를 정하면 형상 시험이 필요하다. 이 특징 크기가 측정된 추론 속도·VRAM·모델 파라미터 수는 아니다.
- 자동 중앙 크롭으로 체력바·미니맵·주변 적을 자르지 않는다. 전체 게임 영역을 먼저 정하고 색 정규화와 크기 변환을 분리·버전 고정한다.
- 증강은 연속 구간 전체에 일관되게 적용한다. 작은 밝기/대비 변화부터 비교하고, 좌우 반전은 행동 방향·HUD·규칙까지 대응할 때만 허용한다.
- 작은 정보 손실 시 해상도 상향, 중요 영역 추가 인코더, 더 큰 공간 격자를 비교한다. 장면 설명 출력은 선택 사항이며 한국어 설명 생성이 행동의 필수 단계는 아니다.

## page-07

**05 시간 기억과 연속 구간**

- 원안: 최근 시각 1,024차원 + 직전 입력 임베딩64 + 시간/유효성 → 512차원 투영 → 1층 hidden512 GRU. BC-RNN 연구 R03은 시간 의존성의 근거이며 이 크기의 게임 적합성을 증명하지 않는다.
- 수식 보존:

```text
z_t = CNN(o_t)
h_t = GRU(Fuse(z_{t-3:t}, Embed(u_{t-1}), time_t), h_{t-1})
행동 분포 = PolicyHead(h_t)
```

- 새 에피소드/체크포인트 재시작: GRU와 특징 이력 초기화. 사람 인수: 기억을 유지하며 사람의 실제 최종 입력으로 갱신. 반환: 현재 화면/실제 입력 이력 연결. 큰 관측 단절: 입력 중지, 경계 표시, 재동기화. 모델/전처리 교체: 예전 GRU·특징 캐시 재사용 금지.
- 학습은 128 판단 시점, 앞32 준비(burn-in), 뒤96 유효 정답에 손실. 30Hz에서 전체 약4.27초, 손실 구간3.2초. 최근4 특징을 만들기 위해 앞3 관측을 추가 읽거나 유효 마스크와 패딩을 사용한다.
- 준비 구간은 현재 모델로 수행한 뒤 역전파를 시작한다. 시간축을 섞거나 다른 에피소드·잘린 클립을 연결하지 않는다. 더 긴 의존성은 준비/펼침 길이를 비교한다.
- GRU가 수분 전략 기억을 보장하지 않는다. 예전 모델 hidden state는 보편적인 재학습 정답이 아니다.

## page-08

**06 컨트롤러 행동 출력**

- 행동 이름 하나 대신 다음 제어 구간의 전체 입력 상태를 출력한다. 일반 버튼은 눌림/해제, D-pad는 중립+8방향=9범주, 좌우 스틱의 각 축은 33구간(중심0 포함), 트리거 각 축은17구간을 제안한다. 아날로그 원본 값은 별도 보존한다.
- 장치 프로필에서 D-pad 충돌 규칙, 축 범위·데드존·버튼 순서를 버전 고정한다. 메뉴·리셋·종료는 정책 밖 운영 명령이다.
- 조건부 출력 제안: `π(a_t | h_t) = ∏_j π(a_{t,j} | h_t, a_{t,<j})`. 앞 요소를 참고해 다음 요소를 고르지만 완성 상태는 한 제어 시점에 전송한다. 학습은 앞 요소 정답, 실행은 선택값을 조건으로 사용한다.
- 사용하지 않는 장치 요소는 출력/손실에서 제외한다. 합법 행동 마스크는 샘플링 전 적용한다. PPO에서는 샘플링 행동을 나중에 다른 입력으로 조용히 치환하면 로그확률 계약이 깨진다.
- 같은 버튼 상태를 반복 출력하면 유지, 바뀌면 해제한다. 30Hz≈33.3ms보다 짧은 탭이 중요한 게임은60Hz 또는 탭 표현을 비교한다. 입력 사건 정밀도를 영상 FPS에 맞춰 줄이지 않는다.
- 스틱33구간의 축 간격은 `2/(33-1)=0.0625`다. 정밀 조준 적합성은 미검증이며 더 많은 구간/연속 분포로 교체 가능하도록 행동 규격을 원본과 분리한다.

## page-09

**07 모방 학습 설계**

- 검토된 적절한 사람 행동만 모방 정답으로 쓴다. 에피소드 성공 여부 하나로 모든 시점에 같은 정답을 부여하지 않는다. 현재 정답 입력은 관측에서 제외하고 지원 행동 요소만 손실에 포함한다.
- 수식: `L_BC = - Σ_t m_t w_t log πθ(u_t | o_≤t, u_<t) / Σ_t m_t w_t`. `m_t`는 정답 마스크, `w_t`는 중요도, `u_t`는 최종 전송 입력. 분모0 구간은 제외한다.
- 검토된 시연은 기억/손실 모두 사용. 자율 AI 구간은 연속 문맥으로 가능하지만 BC 손실은 기본 제외. 검토된 교정은 해당 시점만 정답. 인수 경계·정렬 불명 구간은 손실 제외하며 문맥 사용도 품질로 결정. 실패 에피소드의 적절한 행동은 구간 검토 후 사용할 수 있다.
- 소량 자료로 입력/정답 정렬부터 검사한다. CNN을 고정하고 GRU/출력 학습 → 필요 시 CNN 일부/전체 낮은 학습률 미세조정. 시각과 시간 모듈을 동시에 크게 바꾸는 실험은 기준선 이후다.
- 여러 프레임 CNN 역전파는 추론보다 큰 메모리를 요구한다. 128시점 학습이 소형 GPU에서 바로 된다고 가정하지 않는다. 특징 캐시는 CNN을 고정한 실험에서만 재사용한다.
- 기존 시연·누적 교정·대표 정상 구간을 함께 추출한다. 최신 교정만으로 덮어쓰지 않고 실환경 과제 성과로 후보를 선택한다. 손실 최저 후보가 가장 잘 플레이한다는 보장은 없다. R03.

**08 사람 개입·교정 설계**

- DAgger는 모델이 방문하는 상황에 전문가 행동을 추가하며, HG-DAgger는 사람이 조작권을 인수하는 접근을 다룬다. 원안은 그 문제의식을 참고하지만 논문의 불확실성 임계값 학습까지 재현하지 않는다. R01·R02.
- 상태별 전송: 시연=사람, AI 실행=AI 제안, 인수=사람만, 복구/교정=사람, 명시 반환 이후=AI. 제안/최종전송/관측/결과를 따로 기록한다. 인수 시각과 경계 불확실성을 보존한다.
- 교정 전은 실패 분석·기억 문맥, 교정 중 검토된 사람 행동은 BC 정답, 교정 뒤는 복구 유지 평가다. 개입 전 AI 행동을 개입했다는 이유만으로 전문가 정답으로 바꾸지 않는다.
- 반복 실수에는 실패 후 복구뿐 아니라 실패 전 예방 시연을 추가한다. 동일 시작 상태로 되돌릴 수 있으면 재시연, 없으면 다음 유사 상황에서 더 일찍 개입한다.
- 이유 예시: 회피 타이밍, 길 찾기, 화면 놓침, 잘못된 조작, 판정 불확실. 성공한 교정도 정렬·적절성을 검토한다. 무개입 자체는 행동 정답 보증이 아니다.
- 운영 모델 고정 → 참여 실행 → 자료 검토 → 기존 시연+누적 교정 학습 → 별도 평가 → 에피소드 경계에서 승인 모델 적용. 개입 횟수와 사람 조작 시간 모두 줄어드는지 본다.

**09 자율 강화학습과 자가대전**

- BC/교정 효과 이후, 검증 가능한 보상과 안정 재시작이 준비되면 같은 CNN·GRU에 가치 출력을 붙이고 순환 PPO를 검토한다. VPT는 모방→후속 강화학습 사례이지 규모/성능의 직접 재현 보증은 아니다. R05.
- 과거 시연·교정은 별도 BC 손실, 새 현재 정책 자율 경험은 PPO/가치 손실, 오래된 AI 경험은 분석/별도 오프라인 학습 후보, 사람 인수 경험은 교정으로 분리한다.
- PPO에 성공 에피소드만 선별하거나 과거 자료를 무한 재사용하지 않는다. 수집 정책 버전·선택 행동 로그확률·보상·terminated/truncated·유효 마스크를 보존한다. 순환 학습에는 순서/초기 기억/준비 구간도 필요하다. R06·R16.
- 성공·실패·진행도를 먼저 정의하고 화면에서 추정한 점수/체력은 추정 방법과 신뢰도를 남긴다. 보상 증가가 과제 성공과 일치하는지 별도 확인한다.
- 첫 교정 수집과 RL 회차는 분리한다. 긴급 인수 궤적은 개입 이후 보상을 이전 AI 행동으로 전파하지 않고 검토 대상으로 격리한다. 중단 실패를 숨기면 낙관 편향이므로 중단률도 보고한다.
- 자가대전은 양측을 제어하는 대전 환경에서 상대 버전·상대 풀·시작 조건·고정 평가 상대를 정한 뒤 채택한다. 싱글플레이 필수 기능이 아니다.
- 영상에는 선택하지 않은 행동의 결과가 없으므로 시뮬레이터 대체물이 아니다. 저장 경험만 이용한 오프라인 RL은 분포 밖 행동 가치 문제를 별도 검토한다. R15.

**10 경험 데이터의 계층과 출처**

- 원본 경험: 화면·입력 사건·최종전송·시각·결과를 수정 없이 보존하고 삭제는 보관 정책으로 관리. 해석: 장면·개입 이유·BC 마스크·보상 추정은 라벨 버전 추가. 학습 버전: 에피소드/시간/전처리/분할 목록을 동결·해시. 모델·평가: 설정·가중치·자료 버전·성과·승인 상태.
- 세션은 수집 실행, 에피소드는 시작에서 종료까지 과제, 구간은 그 안의 연속 시간 범위다. 중복 없는 ID가 필요하다. RLDS 구조를 참고하되 전송 시각/교정을 확장한다. R07.

- 여러 데이터셋은 같은 영상의 ID와 시간 범위를 참조하며 복사하지 않는다. 파일 경계와 에피소드 경계는 달라도 학습 연속 구간은 에피소드 경계를 넘지 않는다.
- 입력 없는 기존 영상은 분류/검색/시각 특징 학습에 가능하지만 정확한 버튼 정답이 있는 BC 자료와 동일하지 않다. VPT도 입력 자료로 행동 추정기를 만든 별도 단계를 거쳤다. R05.
- 부록B는 논리 필드이며 라이브러리·샤드 크기·인덱스 구현은 프로젝트 결정이다. 로컬 인덱스가 기본이고 Hub 업로드는 필수가 아니다.

**11 시간 정렬과 데이터 품질**

- 최소 사건 시각: 관측 경로에서 화면 준비, 사람/모델 판단, 장치 전송. 장치/호스트 시계가 다르면 기준 시계 변환·오차·드리프트를 기록한다. 단조 시계와 영상 PTS 대응표를 유지한다.
- 품질 원칙: 판단 전에 사용 가능했던 관측만 선택; 눌림/해제/축/최종전송 보존; 누락/중복/손상/지연 식별; 성공/실패/시간제한/수동중단 구분; 연속성이 있는 구간만 연결; 같은 세션·출처의 파생물이 train/eval을 넘지 않게 분리.
- 실패 처리: 미래 프레임 제외, 짧은 탭 손실·불명 상태 격리, 빠진 시간 이어 붙이지 않기, 모르는 결과는 미확정, 다른 클립은 별도 구간, 파생 영상도 원본별 재분할.
- 사람이 보는 화면과 캡처 화면의 지연은 다를 수 있다. 원본 사건 시각을 수정하지 않고 정렬 규칙을 버전으로 남긴다. 반응 시간을 임의 상수로 빼 모든 행동을 과거로 옮기지 않는다.
- 표시 시각과 인코더 패킷 순서를 혼동하지 않는다. 원본 frame ID·저장 PTS·파일 오프셋·코덱을 연결한다. 파일 생성 성공만으로 프레임 손실 없는 수집이라고 판단하지 않는다. R09.
- 전이 `(o_t,a_t,r_t,o_{t+1})`에는 행동 구간과 다음 관측 관계가 확인되어야 한다. 마지막 관측 부재/큰 공백은 BC와 RL의 목적별 마스크로 명시한다.

**12 영상 보관 정책**

- 교정/실패만 저장하는 편향을 막기 위해 성공·정상 이동·대기·여러 시작 조건도 무작위/구간별 선별한다. 보존 사유와 알 수 있는 원래 수집분포/선택확률을 기록한다.
- 20% 보존은 용량 계산 예시이며 강제 상한이 아니다. 초기 교정 증가로 보호 자료가 많아질 수 있다. 한도 도달 시 보호 자료를 몰래 지우지 말고 기록 범위 축소 또는 수집 중지를 선택한다.

**14 저장 용량 예산**

- 계산식: `영상 GB = 평균 Mbps × 0.45 × 시간(h)`. GB=10^9바이트, TB=1000GB. 오디오·컨테이너·입력·모델·캐시·백업은 영상 계산에서 제외한다.

| 평균 비트레이트 | 1시간 | 1000시간 |
|---|---:|---:|
| 0.5Mbps | 225MB | 225GB |
| 1Mbps | 450MB | 450GB |
| 2Mbps | 900MB | 900GB |
| 4Mbps | 1.8GB | 1800GB |

- 예시: 1000시간 전체0.5Mbps=225GB, 합집합20% 추가4Mbps=360GB, 둘을 동시에 저장하면585GB. 전체4Mbps=1800GB 대비 `1-585/1800=67.5%` 감소. 계산 결과이지 화질/학습 보전 실험이 아니다.
- 4Mbps×60초 압축 버퍼≈30MB. 디코딩 프레임/대기열 메모리는 별도다. 사건당128바이트×초당60회 가정이면 시간당27.648MB, 1000시간27.648GB다. 실제 필드·직렬화에 따라 달라진다.
- 585GB+27.648GB=612.648GB에도 모델·로그·캐시·백업 등은 빠져 있다. 전체 예산은 보호 영상+자율 영상+입력/메타데이터+모델/실험+캐시+백업+여유 공간이다.
- 20% 보존과67.5% 절감이 학습 성능 유지의 근거가 될 수 없다. 실제 과제 평가가 필요하다.

**15 재생 기반 저장과 재학습**

- 디스크 절약 대신 재생 계산/대기 시간이 든다. 자주 쓰는 구간만 캐시하고 캐시 생성 작업을 학습기로부터 분리한다. 원본 기록·게임·코어가 없으면 특징 캐시만으로 시각 모델 재학습은 불가능하다.
- 녹화에는 선택하지 않은 행동의 결과가 없다. 재생 기록, 실제 환경, 미래 예측 모델은 서로 다르다.

| 완전 자율 | 무개입 성공률·진행도; 개입 뒤 승리를 자율 성공으로 세지 않음 |
| 사람 의존도 | 개입/에피소드, 사람 조작 시간 비율; 횟수와 시간을 함께 확인 |
| 교정 효과 | 동일 실패 재발률, 복구 성공; 예방과 복구 분리 |
| 기존 능력 | 정상/기본 행동의 성과 차이와 퇴행 |
| 행동 | 버튼 사건 precision/recall, 시점 오차, 축 오차; 대부분 버튼 off인 정확도 착시 배제 |
| 실행 | 전체 판단 지연 p50/p95/p99, 관측 나이, 누락률 |
| 저장 | GB/h, 유효 구간 비율, 재생 일치 |

- 프레임 랜덤 분할이 아닌 세션/에피소드/원본 출처 그룹 분할. 파생 영상과 같은 시작 상태의 재생 복제 누출도 관리한다. 새 구간/시작/화면 조건 일반화는 별도 holdout이다.
- 운영/후보는 같은 시작 조건으로 비교하고 가능한 여러 학습 시드와 충분한 평가 에피소드를 사용한다. 성공률의 분모, 중단 수, 신뢰구간 또는 반복 변동을 함께 보고한다.
- 후보 선택 validation과 최종 test를 구분한다. 최종 실패 사례를 다음 학습에 쓰면 더 이상 미관측 test가 아니므로 새 시험 집합/변경 이력을 만든다.
- 배포는 자율 성과 또는 사람 의존도의 의미 있는 개선과 기존 능력·지연·데이터 품질 허용 범위를 동시에 만족할 때만 한다.

## page-20

**18 실시간 실행과 장애 처리**

- 30Hz의33.3ms 예산에는 캡처·전처리·CNN·GRU·행동·전송을 포함한다. 관측 나이와 계산 시간을 따로 관리한다. 실시간 게임이 추론을 기다린다고 가정하지 않는다.
- 최신 유효 프레임 우선, 유한 대기열, 결정 기한을 둔다. 한 스텝씩 멈추는 시뮬레이터와 실제 시간 실행은 별도 모드로 기록한다.
- 긴급 인수는 추론 완료를 기다리지 않고 AI 전송 차단. 관측 지연/중지는 설정된 중단·중립·가능한 일시정지. 모델 예외/수치 이상은 추가 AI 입력 차단. 장치 해제는 재전송 반복 중지. 기록/용량 실패는 보호 자료 유지 후 수집 제한. 반환은 상태 확인 후 명시 전환.
- 각각 인수 시각/전후 입력/경계, 관측 나이/누락/중단 사유, 모델 버전/예외, 전송 확인, 누락 범위/정리 기록, 반환 시각/정책 버전을 남긴다.
- 눌린 버튼이 남지 않게 최종 상태를 원자적으로 전환한다. 정상 인수와 전체 중단은 다르다. 인수 때 항상 먼저 전체 버튼을 풀면 불필요한 동작이 생길 수 있어 장치별 전환 규칙을 시험한다.
- 중립/일시정지는 게임 내 안전을 보장하지 않는다. 연결 불명 시 자동입력을 멈추고 사람에게 넘긴다. 결제·삭제·계정·시스템 메뉴는 첫 정책 범위 밖이다.

**19 버전·재현성·로컬 운영**

- 환경: 게임/빌드/실행 방식/시작 상태/입력/화면/허용 범위. 데이터: 원본 해시/구간/출처/라벨/분할. 전처리·행동: 크기/색/정규화/정렬/축구간/버튼순서/마스크. 모델: 구조/가중치/기억/입출력/라이브러리. 학습: 초기 가중치/자료/시드/설정/옵티마이저/체크포인트. 평가: 조건/시행수/지표/중단/후보/승인자/복구 대상을 연결한다.
- 승인 모델은 읽기 전용, 후보는 별도 가중치. 기본 교체 시점은 에피소드 경계이며 직전 승인 버전을 유지한다. 가중치만 아니라 전처리·행동·정규화·기억 초기화까지 묶음 교체한다.
- 출력 차원/버튼순서 불일치는 로드를 거부한다. 이어 학습할 checkpoint와 inference 모델을 구분한다.
- 로컬은 판단·실행·기록·학습·평가를 자체 장치에서 수행한다는 뜻이다. 최초 패키지/사전학습 다운로드와 운영 중 네트워크 의존은 다르다. 필요한 파일 확보 후 오프라인 실행을 점검한다.
- 캡처/로그에 계정·채팅 등이 포함되지 않게 범위를 제한한다. 자동 외부 전송/Hub 업로드/원격 실험 추적은 기본 비활성. 보호 자료 백업과 복구 시험 비용 포함.
- 게임·추론·영상 인코딩·학습이 자원을 경쟁하므로 첫 운영은 플레이/기록과 재학습 시간을 분리한다. 장비에서30Hz를 측정 없이 보장하지 않는다.

- 원안은 환경/데이터/모델/실험/품질/승인 명세를 제공하며 실행 코드나 폴더 생성 완료를 주장하지 않는다.

**부록 D 용어와 결정 기록**

- 정책/행동 모델=관측/이력→다음 입력 분포/값. 추론=기존 가중치로 현재 행동 계산. 학습=정답·보상으로 가중치 갱신. CNN=화면 특징 변환. GRU=관측/행동 정보를 다음 시점에 전달하는 내부 상태.
- BC=검토된 사람 관측/행동 모방. 교정=AI 실행 중 사람이 인수해 검토된 행동 추가. 자율 플레이=직접 사람 조작 없이 실행하며 그 자체로 학습은 아님. 자가대전=과거/다른 상대 정책과 경쟁. PPO=현재 정책 수집 경험 중심 갱신 경로.
- 순환 버퍼=최근 구간 임시 보존 후 오래된 것 덮기. 데이터셋 버전=사용 원본/구간/검토/전처리/분할 고정 목록. 캐시=원본/재생으로 재생성할 계산 결과. 후보/운영 모델=평가 전 새 모델/승인 후 실사용 모델.
- v1.0 결정: 외부 API 중심 대신 로컬 시각 행동 정책; 시연→실행 교정; CNN·GRU/복합 입력; 보호 자료와 선별 자율 경험; 검증된 에뮬레이터에서만 재생 추가.
- 첫 완료 기준은 단일 과제의 교정 효과. 지원 게임·장비 성능·최적 값·최종 용량은 실험 전이다. 변경 시 바뀐 결정·이유·근거 실험·영향 데이터/모델 버전을 함께 남긴다.
