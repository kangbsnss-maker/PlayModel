# 연구 검토와 실현 가능성

검토일2026-09-26. 결론: **단일 게임의 짧은 과제에서 BC→검토된 사람 교정의 효과를 측정하는 로컬 프로그램으로 진행할 수 있다.** 범용 장르 플레이어·장시간 자가학습·현재 장비의 실시간 성능은 아직 입증되지 않았다. 연구 검토와 구조 결정을 최고 Astra 추론 작업으로 수행했으며, 이는 별도 실행된 게임/학습 벤치마크나 원저자의 인증을 뜻하지 않는다.

근거는 [원본29쪽](page-notes.md), [출처 확인](sources.md), [구현 설계](../architecture.md)다. 원안은 이미 인과 정렬·단일 조작권·검토 마스크·데이터 버전·독립 평가를 중시한다. 이번 보완은 이를 실행 가능한 개발 순서와 현재 호스트 제약에 맞추는 데 집중한다.

## 구현 전에 보완한 사항

1. **게임 연결이 최대 선행 위험이다.** 관측을 얻는 것과 허용된 입력을 전송·확인하고 반복 reset하는 것은 다른 기능이다. 합성 환경으로 기록/인수 계약을 확인한 뒤 첫 게임 하나에서 capability를 검증한다. 화면 정책에 내부 상태가 몰래 들어가는 어댑터는 별도 진단 경로로 분리한다.
2. **학습 단위는 시간 길이도 함께 남긴다.** 128시점은30Hz에서4.27초지만10Hz에서는12.8초다. 현재 초안10Hz와 원안30Hz를 같은 학습 조건으로 비교하지 않는다. 빠른 입력은 정책 주기와 별개로 원본 사건에서 보존한다.
3. **frozen CNN 캐시에도 정확한 경계가 필요하다.** 투영층이 업데이트되는데 그 뒤256차원 특징을 재사용하면 잘못된 학습이다. 투영 전 spatial feature 캐시 또는 투영도 고정한 캐시를 명시하고 모든 관련 버전을 key에 넣는다.
4. **6GB VRAM은 작게 시작할 근거이며 성공 보장이 아니다.** 단일 추론과128프레임 CNN 역전파의 메모리는 크게 다르다. CNN 고정·microbatch1·짧은TBPTT·소규모 데이터부터 측정한다. 게임/녹화/학습 동시 사용을 기본으로 삼지 않는다.
5. **중재에는 늦은 추론 결과 경합 방지가 필요하다.** 사람 인수 시 control epoch를 올려 이전 제안을 폐기한다. 단순 UI 토글만으로 조작권 보장을 주장하지 않는다. 정상 인수와 fault 중립 요청은 서로 다른 전환이다.
6. **전송·수신·적용의 unknown을 보존한다.** 장치 전송 성공을 게임 명령 성공으로 적지 않는다. 사람의 인지 결정 시각도 원본 이벤트에서 측정되지 않으면 proxy로 표시한다.
7. **보관 선별과 평가 선별을 구분한다.** 교정/실패만 보존하면 정상 행동이 퇴행할 수 있다. 정상 표본을 남기고 저장 최적화 전후 성과를 비교한다. PPO용 현재 정책 수집 자료를 성공한 회차만 남겨 학습하지 않는다.
8. **모든 중단을 같은 truncated로 처리하지 않는다.** 정상 시간제한은 최종 관측으로 bootstrap 가능하지만 사람 인수/센서 손상은 오염 경계다. [Gymnasium](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/) 규약 위에 출처/품질 마스크를 추가한다.
9. **일반화 수준을 나눈다.** 같은 시작 조건의 반복 성공, 새 시작/맵 성공, 다른 게임 전이는 서로 다른 주장이다. 최초 성과로 장르 전체 학습을 선언하지 않는다.
10. **유튜브 제작 원본을 독립 보존한다.** 저화질 학습 입력/사건 선별만으로 편집의 전후 문맥·음성·정상 플레이를 복원할 수 없다. 고화질 촬영과 세션 타임라인을 별도 매핑하고 사용한 소스를 pin한다.

## 바로 채택하지 않을 것

- **VPT식 대규모 무라벨 영상 학습:** [VPT](https://arxiv.org/abs/2206.11795)는 행동 라벨로 inverse dynamics를 학습하는 단계를 포함한다. 현재 자료·라벨·6GB 장비에 맞는 첫 기준선이 아니며 인터넷 영상만 모으면 버튼 정답이 생긴다고 설명하지 않는다.
- **대형 범용 VLA/세계모델/LLM 제어:** 첫 과제의 데이터·지연·교정 문제를 분리하기 어렵다. 실제 필요가 나타나면 별도 실험으로 검토한다.
- **Pluto를 그대로 가져온 시각 플레이어:** [제작자 저장소](https://github.com/tscmoo/pluto/blob/main/README.md)는 BWAPI 브루드 워 인터페이스와 바이너리 배포를 설명한다. 콘솔 화면+패드 조건의 학습 구현을 제공한다는 증거가 아니다.
- **영상 재생을 환경 대체로 간주:** 다른 행동을 골랐을 때의 결과가 필요하면 실제 환경/검증된 시뮬레이터가 필요하다. `.bk2`도 특정 환경/버전의 재생 일치를 직접 확인해야 한다.
- **최신 ML 패키지 일괄 설치:** 현재 driver560.94에서 CUDA13의580이상 조건을 만족하지 않는다. [NVIDIA 공식 호환 문서](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)를 바탕으로 CUDA12계열 후보를 실행 시험 후 고정한다.

## 자원 계산과 실측의 구분

확인된 정보는 GPU6144MiB, RAM약31.93GiB, 여유 공간약609.56GiB, Python3.12.13, git/ffmpeg/nvidia-smi 탐지다. CUDA tensor·모델 forward/backward·캡처·입력·인코딩 동시 성능은 아직 시험하지 않았다.

원안585GB 영상+27.648GB 수치=612.648GB는 **십진GB**다. 약570.57GiB이며 여유609.56GiB와 단순 숫자 비교하면 안 된다. 남는 약39GiB에도 고화질 제작 원본·작업 캐시·백업·게임/모델이 들어가야 하므로1000시간 운영을 권하지 않는다. 1시간 파일럿에서 실제 저장률/수집 누락/화질을 측정해 시작 예산과 여유 공간 하한을 정한다.

모델 캐시의 계산도 중요하다.30Hz에서 `[512,3,5]` float16 spatial cache는1.65888GB/h,256차원 float16 cache는55.296MB/h다. 작은 후자만 저장할 수 있는지는 투영층까지 고정했는지에 달렸다. 파일 포맷/인덱스 오버헤드는 이 계산에 없다.

## 준비 코드 독립 검토

`src/playmodel/cli.py`, `doctor.py`, `profiles.py`, 프로필 템플릿, `scripts/verify_preparation.py`, README/개발 안내/pyproject를 읽었다. 현재 실행 범위는 준비 도구로 한정되어 있고 `runtime_ready=false`, null 초안, 엄격한 키/숫자/중복 검사는 문서와 맞는다. 게임 제어·GUI·학습이 구현되었다는 잘못된 경계는 발견하지 않았다.

보존 verifier의 초기 버전은 존재하는 원본만 hash를 비교해 원본 일부 소실을 pre-delete 단계에서 놓칠 수 있었고 dimensions도 양수만 확인했다. root에 보고한 뒤 **29개 원본의 존재·SHA256·bytes·실제PNG IHDR 크기를 모두 요구하도록 수정**된 구현을 다시 읽어 해결 확인했다. cleanup 후에는 원본 부재와 정확한 receipt↔manifest 대응을 검증한다. 테스트 수/실행 결과의 최종 증거는 root 검증 기록을 따른다. 이 검토는 준비 코드의 범위 검토이며 미래 런타임 전체 감사는 아니다.

## 다음 입력과 아직 모르는 것

필수 다음 입력은 첫 게임/장르, 실행 플랫폼, 접근 가능한 캡처·입력 경로, 반복할 짧은 과제와 성공 판정이다. 사람 조작 장치와 시연 가능 시간, 저장 예산, 첫 영상의 길이/형식도 구현 우선순위를 정할 때 필요하다. 이 항목은 **개발 준비 완료를 막는 질문이 아니라 M1 착수 입력**이다.

GitHub 소유자·저장소 이름·공개 여부·코드 라이선스는 원격 게시 직전에 확정한다. 게임별 학습/녹화/게시 허용 범위와 음원 처리는 게임 선택 뒤 확인한다. 현재 특정 게임의 권리나 유튜브 수익화를 확인/보장한 상태가 아니다.
