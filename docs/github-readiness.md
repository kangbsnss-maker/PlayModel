# GitHub 공개 준비

사용자가 지정한 저장소는 **[kangbsnss-maker/PlayModel](https://github.com/kangbsnss-maker/PlayModel)**이다. 공개 저장소이며 로컬 `origin`을 해당 HTTPS 주소로 설정했다. 브라우저 인증 후 실제 GitHub 계정명 `kangbsnss-maker`와 push 권한을 확인하고 프로젝트의 인증 사용자로 고정했다. 게시 목적은 [학습 목적](vision.md)을 따른다.

2026-09-27 게시 준비 검사: 로컬 테스트 475개, 문서 링크 95개, 데이터 제외 경계 검사를 통과했다. 첫 게시 대상은 코드·테스트·문서·템플릿 184개 파일, 약 1.63 MB다. 비밀키 패턴과 대용량·런타임 자료 포함 검사에서 발견 사항이 없었다. 이 검사는 학습 목표 달성이나 실력 향상을 뜻하지 않는다.

## 저장소에 들어갈 것

코드, 테스트, CI, 설정 템플릿, 연구를 재정리한 메모, 결정 기록. 원본 이미지 29장은 전체 분석 후 사용자 지시에 따라 삭제하며 파일명·해시·페이지별 메모를 남긴다. 해시는 동일성 기록이며 이미지를 복원하는 백업이 아니다.

학습 데이터·모델 가중치·녹화본·게임 파일·개인 설정은 로컬 폴더로 분리한다. Git LFS와 데이터 저장소는 실제 배포할 아티팩트가 정해진 후 선택한다. `.gitignore`는 이미 추적된 파일에서 비밀을 제거하지 않으므로 첫 커밋 전 검토가 필요하다.

## 첫 공개 전 결정

- GitHub 소유 계정, 저장소 이름, public/private.
- 코드 배포 라이선스와 저작권자. 지금은 LICENSE를 임의로 부여하지 않는다.
- 연구 메모에 남긴 이미지 유래 내용의 공개 가능 범위.
- 첫 게임의 자동 조작·녹화·공개 정책. 게임별 영상·음악 권리 검토는 별도 기록.

## 게시 절차

1. `python scripts/verify_preparation.py` 실행.
2. `git status --short`, `git diff --check`, `git ls-files`로 포함 파일 확인.
3. 첫 커밋 대상 지정 후 `git diff --cached`로 코드·문서·비밀·대용량 파일 검토.
4. 저장소 이름·공개 범위·라이선스 결정 후 GitHub 저장소 생성 및 remote 설정.
5. 승인된 파일 커밋·push 후 GitHub Actions 결과 확인.

GitHub 게시와 유튜브 게시는 별도 작업이다. 계정 토큰·OAuth 파일은 프로젝트 공개 문서나 설정 템플릿에 넣지 않는다.
