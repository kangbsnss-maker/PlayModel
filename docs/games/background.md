# Brotato 백그라운드 입력과 캐릭터 수집

2026-09-27. 요구사항: 사용자가 시스템 마우스와 전경 창을 계속 사용하고, 프로그램은 Brotato만 조작한다. 물리 커서 이동·전경 강탈·전역 입력을 성공 경로로 사용하지 않는다. 백그라운드 캡처 가능성과 백그라운드 입력 지원은 별도 능력이다.

## 공식 소스로 확인한 제약

확인한 Godot `3.x` Windows 구현은 `WM_MOUSEMOVE`의 client 좌표를 읽지만 입력 전달에 `window_has_focus` 조건을 둔다. 마우스 버튼은 별도 경로이며 `SetCapture`를 호출한다. 키 메시지는 입력 버퍼로 처리되므로 마우스 호버와 지원 여부가 다를 수 있다. 로컬 로그의 엔진은 `3.7.dev.custom_build.74e86be54`이며 공개 분기와 동일한 빌드라고 가정하지 않는다. [Godot Windows 소스](https://github.com/godotengine/godot/blob/3.x/platform/windows/os_windows.cpp)

`PostMessage` 성공은 메시지 큐에 넣었다는 뜻이며 게임이 처리·적용했다는 확인이 아니다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)

## 로컬 확인 범위

실제 백그라운드 키보드 메시지로 캐릭터·SMG·위험도 0/무한 모드를 선택하고 첫 웨이브 진입·Esc 일시정지를 확인했다. 추가 이동 시험에서 게임 타이머 19→18→17→15, 캐릭터 위치 변화, 재료 30→33과 경험치 증가를 확인했다. 관측은 `data/raw/brotato-movement-probe/`의 20260926T163842Z부터 163846Z 세션과 `report.json`에 남긴다. 이 과정에서 설정을 변경하지 않았다. 전후 데스크톱 상태가 같았으며, 중간 모든 사용자 입력의 비간섭을 이 값만으로 증명하지는 않는다.

마우스 호버·클릭은 중단하고 전경 활성화·전역 입력 경로를 폐기했다. 현재 확인은 제한된 키보드 메뉴 및 이동 시험이다. 전체 판, 지속적인 정책 제어, 학습 개선까지 성공했다는 뜻은 아니다.

설정 경로는 `%APPDATA%\Brotato\<SteamID>\settings.json`, 로그는 `%APPDATA%\Brotato\logs\godot.log`다. 로그에 게임 버전 `1.1.15.4`가 표시된다. 변경 전 읽기 조사에서 다음 디스크 값을 확인했다. 세이브 내용은 열지 않았고 파일을 변경하지 않았다.

| 설정 키 | 확인 값 | 해석 경계 |
|---|---|---|
| `settings.pause_on_focus_lost` | `true` | 이 값이 그대로인 상태에서 실제 배경 진행 확인; 정지 원인으로 확정하지 않음 |
| `settings.on_lost_focus` | `1` | enum 숫자의 의미는 미확정 |
| `settings.limit_fps` | `false` | 일반 FPS 제한 값이며 별도 배경 제한 부재의 증명은 아님 |
| `settings.background` | `0` | 이름만으로 배경 FPS 설정이라 해석하지 않음 |
| `settings.manual_aim` | `false` | 디스크상 수동 조준 비활성 |
| `settings.language` / `fullscreen` | `zh` / `true` | 캡처·UI 비교 조건 |

`background_fps`라는 키는 찾지 못했다. 디스크 설정과 실행 중 메모리 값은 같다고 단정하지 않는다. 위 표는 읽기 조사 기록이며 이번 배경 이동을 위해 설정을 바꾸지 않았다. 이후 변경이 필요하면 담당자가 백업·적용·재확인을 수행한다. 성공 검증은 다른 앱을 전경에 둔 채 게임 내 시간·이동·결과를 관찰하는 것이다. 창 캡처 FPS나 벽시계 경과만으로 이를 대신하지 않는다.

## 메뉴 스크롤을 인식하는 범위

`scroll.py`는 메뉴 종류·해상도·트랙 영역이 확인된 화면에서 손잡이 위치와 위/아래 남은 영역을 읽는 표준 라이브러리 모듈이다. 현재 보정 대상은 `1.1.15.4`, 중국어 접근성 탭, 1920×1080의 세로 스크롤바다. 메뉴를 스스로 식별하거나 글의 의미를 이해하는 모델이 아니다. 다른 화면·해상도·가림·손잡이 불명은 `unknown`이며 입력을 실행하지 않는다.

실제 캡처 두 장에서 손잡이는 `[223,748)`→`[450,975)`로 내려갔다. 알려진 트랙 끝은 980이므로 둘째 화면에는 5px가 남는다. 이 상태는 `near_bottom`, 아래 추가 이동 가능 여부는 `null`이다. 화면 아래에 닿아 보인다는 이유로 끝을 확정하지 않는다. 경계에 실제 도달한 연속 관측은 확인 상태로 누적하며, 같은 시각의 중복 관측은 누적하지 않는다.

`MenuScrollTracker`는 메뉴 재진입을 별도 ID로 구분한다. 반복 입력 후 손잡이가 안 움직이면 `stalled_unknown`으로 중단한다. 선택 강조만 이동했거나 입력이 전달되지 않았거나 렌더가 멎었을 수 있으므로 이를 목록 끝으로 바꾸지 않는다. 스크롤 위치는 현재 선택 항목의 ID나 모든 항목을 읽었다는 증거가 아니다. 전투 카메라 이동 추정은 별도 인식 경로다.

합성 정상·오류 사례와 Git에서 제외한 실제 두 캡처를 포함해 12개 검사를 통과했다. 실제 프레임이 없는 환경에서는 해당 회귀 검사만 건너뛴다. 이 규칙 구현·검증을 신경망의 스크롤 학습 완료로 보고하지 않는다.

## 선택할 경로

1. **기존 HWND 경로:** 별도 전경 앱을 유지하고 Brotato PID/실행 파일·client 크기를 확인한다. 현재 확인된 키보드 경로를 사용하며 물리 커서 호버·포커스 메시지 위장·전경 입력으로 자동 전환하지 않는다.
2. **키보드 지원 확대:** 메뉴 탐색, 확인 버튼, 전투 이동, 키 해제를 각각 capability로 기록한다. 입력 전 상태·대상을 확인하고 새 화면으로 적용을 검증한다. 메뉴 성공만으로 전체 게임 입력을 지원한다고 표시하지 않는다.
3. **게임 내부 어댑터:** 기존 경로가 부족하면 Brotato 버전과 지원되는 mod 경로를 확인한다. Godot의 `Input.parse_input_event`는 게임 내부 이벤트를 만들 수 있다. `action_press`는 `_input` 호출을 만들지 않으므로 UI 이벤트 경로와 구분한다. 이 API가 외부 Python에서 그대로 호출되는 것은 아니다. [Godot Input 문서](https://docs.godotengine.org/en/3.5/classes/class_input.html#class-input-method-parse-input-event)
4. **가상 패드:** 기존 장치·드라이버·게임 인식을 먼저 조사한다. Godot의 XInput과 DirectInput 경로를 구분하며, 확인한 DirectInput 설정은 `DISCL_FOREGROUND`다. 가상 패드 설치만으로 백그라운드 동작이나 다른 프로그램과의 분리를 보장하지 않는다. 이번 검토에서는 설치하지 않았다. [Godot 패드 소스](https://github.com/godotengine/godot/blob/3.x/platform/windows/joypad_windows.cpp)

## 수락과 수집 속도

- 대상 게임이 전경이 아닌 상태에서 실제 UI/이동 변화가 확인되어야 한다. 전경 유지, 물리 커서·버튼·키 비간섭, 해제 동작을 함께 확인한다. 전후 커서 좌표가 같은 것만으로 중간 간섭까지 없었다고 단정하지 않는다.
- 클릭은 게임의 마우스 캡처 부작용을 확인하기 전까지 독립적으로 미지원 취급한다. 마우스 호버·키보드·클릭·전투 이동을 하나의 성공 플래그로 합치지 않는다.
- 캐릭터당 **4–5초는 목표**다. 지속 실행하는 숨김 캡처/OCR worker와 필요한 ROI를 사용하고, 전송→대상 강조/설명 안정→해당 프레임 OCR→저장의 단계별 시간을 측정한다. 긴 고정 대기로 정확성을 대신하지 않는다.
- `interaction_id`, 대상 셀, 캡처 ID/해시, 관찰 시각, OCR 원문·버전을 연결한다. 이전 캐릭터의 늦은 OCR을 다음 캐릭터에 붙이지 않는다. 제한 시간 안에 대상-설명 대응이 확인되지 않으면 unknown으로 남기고 재시도한다.
- 개발자 판독·메뉴 교정, 로컬 관측 지식, 학습용으로 검증된 궤적을 구분한다. 캐릭터 설명 수집 자체를 정책 학습 완료로 보고하지 않는다.
