# Brotato 로컬 화면 분석 기준선

2026-09-27. 구현은 `src/playmodel/games/brotato/vision.py`. Python 표준 라이브러리만 사용하며 네트워크·GPT·OCR·게임 입력이 없다. 색·연결 영역·직전 위치를 사용하는 실험 기준선이다. 신경망 학습, 전체 자동 플레이, 적/투사체 인식 정확도 검증을 뜻하지 않는다.

## 호출 계약

```python
from playmodel.games.brotato.vision import BrotatoVision

vision = BrotatoVision()
observation = vision.observe(
    frame.pixels,
    frame.metadata["sample_width"],
    frame.metadata["sample_height"],
    observed_at_ns=frame.metadata["capture_started_at_ns"],
    paused=False,
    alpha_mode="ignore",
)
dx, dy, valid = observation.navigation
# 호출자는 최신 프레임·UI·조작권을 별도로 검증한다.
# valid=False이면 이전 이동을 재사용하지 않고 입력을 해제한다.
```

- `navigation`: 정규화한 화면 이동 방향 `(dx, dy, valid)`. 화면 좌표는 오른쪽·아래쪽이 양수다. 실제 입력 전송이 아니다.
- `player`: 흰 캐릭터 영역 중심의 `(x, y)`, 각 축은 0~1. 캐릭터 발 위치·월드 위치가 아니다.
- `pickups`: 녹색 획득물 후보. `label="pickup_candidate"`, 점수 0.4. 재화·XP·회복·효과의 세부 의미를 구분하지 않는다.
- `hazards`: 붉은색·보라색 위험 후보. `label="unknown"`, 점수 0.2. 적·투사체·효과의 세부 의미를 구분하지 않는다.
- `hp_fill_fraction`: HUD 붉은 채움의 근사 비율 또는 `None`. 숫자 OCR, 최대 HP, 피해량, 사망 판정이 아니다. 붉은 채움이 없는 화면은 0 HP로 확정하지 않는다.
- `combat_likely`, `status`, `reasons`: HUD·배경·캐릭터 검사의 결과. `combat_likely=True`만으로 입력하지 않는다.
- `observed_at_ns`, `extractor_version`: 관측 시각·추출기 출처. 같은 시각 또는 역행 시각은 거부한다. 전체 프레임의 나이는 호출자가 검사한다.
- `camera_status`, `camera_shift`, `camera_confidence`: 아래 카메라 계약. 점수들은 보정된 확률이 아니다.

GDI `BI_RGB` 캡처의 알파 바이트에는 투명도 의미가 없으므로 기본 `alpha_mode="ignore"`다. 실제 알파가 있는 BGRA는 `"straight"`로 전달한다. 그 모드에서는 알파 128 미만 픽셀이 검출 근거가 될 수 없다. 두 형식을 추측해서 섞지 않는다.

새 판·캐릭터 교체에는 `vision.reset()`을 호출한다. 알려진 일시정지 화면은 `paused=True`로 전달한다. 이 모듈은 UI 분류기의 대체물이 아니다.

## 검출과 이동

320×180 입력은 내부에서 160×90으로 줄인다. 왼쪽 위 HP/XP/재화, 위 중앙 웨이브·타이머, 잘린 낙하산 반사광이 나타나는 상단 3%를 제외한다. HP·XP 바의 위치와 검은 테두리가 맞고 갈색 또는 회청색 경기장 배경이 충분한 경우에만 후보를 분석한다.

흰 영역은 크기·형상·직전 위치로 제한한다. 검은 눈/입 때문에 인접한 흰 얼굴 영역이 갈라진 경우 합친다. 초기 후보가 비슷한 크기로 여러 개면 `player_ambiguous`로 중립을 반환한다. 현재 프레임에서 캐릭터가 없으면 직전 위치를 현재 위치처럼 사용하지 않는다. 세 번 실패하면 이전 위치를 버리고 다시 획득한다.

색이 맞는 HUD 코인은 획득물에서 제외한다. 실제 캡처에 나타난 흰색/회색 피해 숫자와 바닥 장식을 위험 후보로 승격하지 않는다. 작은 보라색 장식, 붉은 효과, 피격 반짝임, 의상 변화, 좁은 투사체의 오탐·미탐은 여전히 가능하다. 투사체 궤적·속도·충돌 시점을 추정하지 않는다.

이동은 가까운 위험 후보의 반대 방향, 화면 가장자리 안쪽, 가까운 획득물, 중앙 주변 탐색 순이다. 가까운 위험과 획득물이 같은 방향에 있으면 회피가 우선한다. 빈 화면의 탐색은 손으로 정한 기준선이며 학습된 XP 전략이 아니다. 화면 가장자리는 실제 경기장 경계의 대용값이다. 장애물·경로 탐색·지형 경계·최적 속도·생존을 보장하지 않는다.

잘못된 크기·버퍼·NaN 값, 전투 HUD 미검출, 어두운 중앙 메뉴 후보, 대량 색 후보, 캐릭터 미확정은 `navigation=(0, 0, False)`다. 오래된 제안 입력의 해제는 호출자의 단일 writer가 담당한다.

## 카메라·스크롤

이전·현재 경기장 명암 패치에서 여러 구역의 공통 변위를 찾는다. 최소한의 질감과 합의가 없으면 `camera_status="unknown"`, 변위는 `None`이다. 작은 공통 변위 후보는 `"shift_candidate"`, 이번 탐색에서 변위가 검출되지 않은 경우만 `"no_shift_detected"`다. 후자는 카메라 정지의 증명이 아니다.

공통 변위가 있으면 이전 캐릭터 위치의 연속성 판단을 폐기한다. 현재 프레임에서 캐릭터가 독립적으로 식별되면 같은 프레임의 캐릭터→획득물/위험 상대 벡터로 이동할 수 있다. 공통 카메라 변위는 그 상대 벡터에서 상쇄되므로 스크롤마다 이동을 정지시키지 않는다. 현재 위치가 모호하면 중립이다.

탐색 범위는 내부 표본 격자의 ±2픽셀이다. 1920×1080 원본→stride 6 입력→내부 stride 2에서는 원본 약 ±24픽셀이다. 느린 부분 픽셀 이동, 큰 점프, 확대/축소, 반복 무늬, 메뉴 스크롤은 미지원이다. 원본에서 약 324픽셀 세로 이동이 관찰된 두 저장 화면은 이 탐색 범위 밖이다. 이 모듈의 출력으로 월드 속도, 획득물 소멸에 따른 XP 획득, 피격/사망 원인, 메뉴 스크롤 완료를 학습 정답으로 만들지 않는다.

## 첫 실제 pilot 기록의 검출 회귀

`artifacts/brotato-pilot/20260926T164806Z-71aa3af0`의 저장된 원본 BGRA 26프레임을 관측 시각 순서대로 재생했다. 모두 현재 검출기로 이동 방향을 만들었고 마지막 캐릭터 위치도 기록값과 일치했다. 실제 중단 원본이 보존되지 않아 보고된 `player_unknown`의 직접 원인은 재현하지 못했다. 점멸·가림을 원인으로 확정하거나 밝기 임계값을 무작정 낮추지 않았다.

같은 기록의 `ocr/` 원본을 개발자가 직접 확인했다. `20260926T164808Z-8bf57c95`에는 `升级!`, LV.1, HP 16/16이 나타난다. `20260926T164812Z-10186ae9`에는 타이머 0과 `通过!`, `20260926T164814Z-0863e826`에는 `发现道具!` 획득 선택이 나타난다. 이는 개별 화면의 관찰이며 사망·피격 원인이나 학습 성능 증거가 아니다. 메뉴 뒤 캐릭터의 어두운 색은 배경 전체가 어두워지는 효과와 함께 나타난다.

레벨업 화면을 이전 추적 없이 분석하면 작은 흰 글자가 얼굴보다 두 표본 픽셀 많아 잘못 선택되는 문제를 발견했다. 초기 후보의 차이가 두 픽셀 이하이면 모호함으로 거부하도록 보정했다. 직전 원본 프레임으로 추적을 시작한 경우에는 같은 레벨업 화면에서 얼굴 위치를 유지한다. 레벨업 문구 자체를 새로운 캐릭터 라벨로 사용하지 않는다. HP HUD가 남은 웨이브 통과·획득 선택 화면에서도 이동을 차단하는 로컬 회귀 검사를 추가했다.
