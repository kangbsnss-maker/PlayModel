# Brotato 완전 자율 플레이

2026-09-27. 사용자 목표는 **AI가 캐릭터 선택부터 이동·성장·상점·종료·다음 판까지 담당하는 것**이다. 사람 이동이나 카드 선택을 필수 단계로 두지 않는다. 사람이 제공하는 화면·시연은 선택적인 진단·교정 자료다. [ADR 0005](../decisions/0005-brotato-full-run.md)가 이전 카드 선택 중심 범위를 대체한다.

## 확인 범위

Windows Steam 앱 `1942280`, 로컬 로그 버전 `1.1.15.4`, 1920×1080 client 캡처와 로컬 중국어 OCR을 확인했다. 대상 HWND의 백그라운드 키 메시지로 캐릭터·SMG·위험도 0/무한 모드 선택→첫 웨이브→일시정지를 통과했다. 별도 이동 시험에서 타이머 진행, 이동, 재료 30→33 및 경험치 증가도 확인했다. 이는 제한된 실제 제어 증거이며 정책 학습·전체 자율 플레이 완료를 뜻하지 않는다.

**백그라운드 전용**이다. 사용자가 시스템 마우스와 전경 창을 계속 사용하며, 프로그램은 전경 강탈·커서 이동·전역 입력으로 대체하지 않는다. 마우스 호버 실험은 중단하고 확인된 키보드 경로를 사용한다. [배경 입력·스크롤 기록](background.md)에 기능별 증거와 미확정을 구분한다.

공식 상점은 기본 자동 발사, 수동 조준 옵션, 캐릭터·무기·아이템, 웨이브 사이 상점, 적 능력치 접근성 설정을 설명한다. 현재 설치의 설정값은 따로 확인해야 한다. [Brotato 공식 Steam 페이지](https://store.steampowered.com/app/1942280/Brotato/)

공식 업데이트에는 Nightmare 난이도 추가, 캐릭터별 레벨업 제한, 무기별 능력치 계수 변경이 있다. 따라서 Danger 0–5나 고정 능력치 표를 모든 버전에 적용하지 않는다. [공식 업데이트 기록](https://steamcommunity.com/app/1942280/announcements/?l=english)

Abyssal Terrors는 새 지도·캐릭터·무기·아이템·규칙을 추가한다. 설치 파일 존재만으로 DLC 소유·활성화나 특정 규칙 적용을 확정하지 않는다. [공식 DLC 설명](https://store.steampowered.com/app/2868390/Brotato_Abyssal_Terrors/)

## AI가 맡을 전체 흐름

아래는 구현 대상이다. 메뉴 순서와 가능한 행동은 **설치 빌드에서 화면으로 확인**한 뒤 고정한다. 상자와 레벨업의 순서, 시작 무기·지도·모드 선택 분기를 임의로 정하지 않는다.

| 상태 | AI 책임과 확인할 결과 |
|---|---|
| 실행·타이틀 | 게임 창 식별, 정상 시작 경로 선택, 업데이트 알림·미지 화면 구분 |
| 캐릭터·시작 설정 | 해금된 캐릭터, 허용 시작 무기, 지도·난이도·모드 선택; 선택 확정 화면 확인 |
| 웨이브 | 위치·적·투사체·장애물·획득물·체력·시간을 관찰하며 이동; 실제 조준 설정에 맞는 제어 |
| 상자·레벨업 | 전체 제안과 현재 빌드로 수령/재활용·강화·재선택 등 실제 지원 행동 평가; 적용 확인 |
| 상점 | 구매·재선택·잠금·조합·재활용·다음 웨이브. 가격·재화·슬롯·소유 상태·금지 조건 확인 |
| 결과·재시작 | 승리/사망/중단과 최종 빌드 보존, 정상 다시 시작/다음 판 경로 수행 |
| 일시정지·미확정 | 입력 해제, 재관찰, 제한된 복구. 계속 불명확하면 실패 원인을 기록하고 중지 |

고정 시간 동안 클릭을 이어 붙이지 않는다. 모든 제안은 `run_id`, 관측 ID, 현재 UI 상태, 후보 ID, 소유권 epoch, 만료 시각을 갖는다. 입력 뒤 상태·재화·소유 변화로 적용을 확인한 다음 진행한다. 상점이 갱신되면 이전 좌표·후보 제안을 폐기한다. 사람 인수와 전체 중지는 항상 가능하지만 정상 한 판에 사람 조작을 요구하지 않는다.

캐릭터를 AI가 고르는 기능과 성능 시험 조건은 구분한다. 개발 시험에서는 선택 가능 목록을 한 캐릭터·난이도로 제한해도 AI가 메뉴를 직접 통과한다. 전체 선택 전략의 성능은 이후 여러 캐릭터에서 따로 평가한다.

## 캐릭터 특성과 해금 부목표

확인된 키보드 탐색으로 강조 대상과 특성 패널을 연결하고 선택 확정과 관찰을 분리한다. 새 패널의 이름/원문, 중국어 원문, 캐릭터 식별 근거, 특성/수치·조건, 잠금 여부, 관찰/가용 시각, 추출기·보정 출처를 로컬에 보존한다. 이전 대상의 늦은 OCR을 새 캐릭터에 붙이지 않는다. 미해석 조건은 unknown이다. 관측 지식 저장과 개발자의 의미 보정은 정책 가중치 학습이 아니다. 캐릭터당 4–5초는 수집 목표이며 검증된 처리 성능은 아니다.

미해금 캐릭터는 부목표다. 조건 원문→비교·수량·기간·난이도 해석→실행 중 진행→실제 해금 알림/선택 가능 상태를 각각 확인한다. 진행 추정이나 목표 달성 예측만으로 해금 완료를 선언하지 않는다. 생존·진행의 주목표를 임의로 희생하지 않으며, 해금 전략을 시험하는 실행은 별도 목표·평가 조건으로 표시한다.

## 모든 능력치를 고려한다는 뜻

목표는 보유한 능력치·효과를 빠뜨리지 않고 **현재 빌드에서 추가 선택의 가치**를 평가하는 것이다. 모든 숫자를 양수로 만들거나 가장 큰 숫자를 고르는 규칙이 아니다. 관측은 원문, 표시값, 유효값, 단위, 관찰 시각, 출처, 불확실성을 보관한다. 알려지지 않은 수치를 0으로 채우지 않는다.

| 평가 축 | 함께 확인할 맥락 |
|---|---|
| 공격 | 피해량·근접/원거리/원소·공격속도·치명타·사거리와 실제 보유 무기의 계수·등급·효과 |
| 구조물·특수 공격 | 공학 및 구조물/무기별 적용 대상. 일반 피해·공격속도가 모든 공격에 동일하게 적용된다고 가정하지 않음 |
| 생존·이동 | 현재/최대 HP, 재생·흡혈·방어·회피·이동속도, 실제 피격·회복·회피 가능성 |
| 경제·진행 | 재화·가격·수확·행운·획득량과 남은 웨이브, 당장 생존할 투자와 미래 수입의 교환 |
| 보조·특수 | 아이템 문구, 발동 조건·중첩·태그·슬롯·제약, DLC가 적용된 경우 Curse 등 추가 필드 |

캐릭터의 변경 배율·무효화, 하한/상한, 조건부 전환, 반올림, 포화 이후 잔여 이득을 규칙 버전으로 관리한다. 원시 표시값을 임의로 잘라 저장하면 나중에 능력치 전환 효과나 초과분을 평가할 수 없으므로 원본을 유지한다. 계수·상한의 정확한 숫자는 설치 버전 설명과 적용 시험으로 확인하며 위 표는 완성된 게임 공식표가 아니다.

관측된 능력치·효과마다 지원/미지원/미확정 목록을 유지한다. 미지원 효과를 조용히 버리거나 모든 스탯을 반영했다고 보고하지 않는다. 새 아이템·DLC·모드가 추가되면 이 목록과 규칙 검증을 갱신한다.

구매·강화·조합은 현재 상태에서 가능한 행동만 비교한다. 같은 아이템도 캐릭터, 보유 무기, 남은 슬롯, 생존 압박, 재화에 따라 가치가 달라진다. 선택 이후 빌드와 실제 웨이브 성과를 연결하고 미래 상점·결과는 당시 입력으로 사용하지 않는다. “최적 빌드”는 장기 목표이며 보장 가능한 현재 성능이 아니다.

## 다음 실제 구현과 통과 순서

1. **설치·연결 진단:** 실행 경로, 빌드, 언어, 화면·조준·접근성 설정, DLC/모드 상태를 읽고 확인/미확정을 구분한다. 파일과 저장 데이터를 변경하지 않는다.
2. **창·관찰·입력:** 실제 client 캡처와 대상 HWND를 기반으로 배경 입력/해제·중지·기한 초과를 시험한다. 최신 프레임을 우선하고 인식 실패·대상 변경 시 입력하지 않는다. 사용자 전경 창·시스템 커서를 유지하며 보조 프로세스는 숨김 실행한다.
3. **시작 경로:** 키보드로 특성·해금 조건을 확인하고 AI가 캐릭터와 허용 시작 조건을 선택해 첫 웨이브로 진입한다. 확인된 개발 시험 경로를 자동 상태 전환으로 연결한다. 각 전환은 새 화면으로 확인하며 개발자 보정과 자동 정책 실행을 로그에서 구분한다. 메뉴 스크롤 끝을 모르면 무작정 추가 입력하지 않는다.
4. **한 웨이브 연결:** AI 이동→웨이브 종료→실제 등장한 보상/강화→상점→다음 웨이브까지 사람 없이 연결한다. 성공 여부와 별개로 실패를 기록한다.
5. **전체 판:** 시작부터 승리 또는 사망 결과, 기록 확정과 정상 재시작을 반복한다. 이것이 자율 실행의 첫 완료 기준이며 실력 개선의 증거는 별도다.
6. **학습·비교:** 초기 휴리스틱 이동/빌드 정책을 명시하고 고정 기준선으로 보존한다. 자율 자료·선택적 사람 교정·검증된 결과로 후보를 학습하고 판 단위 holdout에서 비교한다.

현재 첫 갱신 파일럿은 8×6 RGB 표본·직전 실제 행동·현재 프레임의 목표 방향을 받는 9방향 선형 softmax 정책이다. 색상/위치 휴리스틱과 초기 방향 선호는 사람이 정한 초기값이며 학습으로 얻은 적 인식·회피·수집 능력이라고 보고하지 않는다. 같은 정책에서 확률적으로 뽑은 실제 전송 행동만 원장에 남기고, 독립 확인된 웨이브 종료/사망의 희소 보상으로 REINFORCE 후보 갱신을 시험한다. 큰 상태·성장 모델을 대체하는 최종 구조가 아니다.

`events.py`는 검증된 동일 전투 HUD의 HP 감소/회복, 레벨 내 XP 진행, 레벨 상승, 재화 변화를 원본 쌍과 연결하는 순수 계약이다. 최대 HP 변경을 피격으로, 재화 증가를 XP 획득으로, HP=0을 사망으로 바꾸지 않는다. 사망은 별도로 검증된 종료 상태가 있어야 한다. 메뉴·정지·새 판·해상도 변경·역행 시각·긴 간격은 비교 기준을 끊는다. **현재 실제 숫자 OCR·휴리스틱 HP 비율·정책 보상에 연결하지 않았다.** 사건 규칙 구현은 게임 메커니즘을 학습했다는 증거가 아니다.

첫 실제 학습은 관측→실제 행동→독립 확인된 웨이브/사망 결과→로컬 파라미터 갱신→checkpoint가 검증될 때 인정하며, 그 후보를 새 실행에서 별도로 평가한다. 재시작·개입·시간제한·입력/해제 실패를 구분하고, 늦은 종료 판독이 이전 제어 실패를 덮지 못하게 한다. 오독한 HP 대신 검증 가능한 결과만 보상으로 쓴다. 메뉴 대기 시간을 생존 보상으로 세지 않는다. 자기 입력을 BC 정답으로 복제하거나 OCR 원문을 저장하는 것으로 이 조건을 대신하지 않는다. 첫 업데이트 성공과 실력 개선은 별도다.

평가 시 캐릭터·난이도·접근성·해금·DLC·모드·이동 정책을 기록한다. 빌드 정책만 비교할 때 이동을 고정하고, 통합 정책은 별도 평가한다. 캐릭터·난이도를 쉬운 쪽으로 바꾼 성과를 같은 조건의 실력 향상으로 보고하지 않는다. 사망·중단·인식 실패를 포함하며 최고 기록 한 판만 고르지 않는다. 전 과정은 로컬이고 외부 GPT 평가자를 사용하지 않는다.
