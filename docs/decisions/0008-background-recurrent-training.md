# ADR 0008 — 실제 플레이와 별도 프로세스 PPO 학습의 중첩

2026-09-27. 반복 자가학습의 정상 실행 경로를 로컬 프로세스 둘로 나눈다.
게임 입력 writer는 기존 수집기 하나뿐이며, 학습 worker는 게임을 조작하지 않는다.

## 실행 순서

1. 고정 원본 정책으로 학습판을 수집하고 증거 manifest를 확정한다.
2. 원본 checkpoint·학습 manifest·학습 설정·구현 해시를 고정한 작업을 저장한다.
3. 숨김 학습 프로세스가 모델·증거를 준비한 뒤 PPO 직전 대기한다. 수집기는 고정 원본
   정책의 새 평가판을 진행하며, 첫 전투 행동의 실제 송신과 기록이 끝나면 학습을 해제한다.
4. 원본 평가판이 끝난 경계에서 학습 결과를 확인한다. 미완료라면 이 경계에서 기다린다.
5. 후보 checkpoint의 출처·해시·재로딩·PPO 수치 검사를 통과한 뒤 후보 평가판을 진행한다.
6. 명시된 연속 실험 모드에서는 다음 사이클의 새 학습판으로 이어간다.

학습 중인 가중치를 플레이 프로세스에 실시간으로 덮어쓰지 않는다. 평가판은 학습에
사용하지 않는다. 같은 rollout을 무제한 재학습하지 않으며, PPO 한 업데이트 내부의
제한된 epochs와 KL 중단은 기존 계약을 따른다. 정책 개선이나 정식 배포 승인은 별도다.

## 저장과 재개

작업 요청과 원본 자료는 수정하지 않는다. 상태·결과는 별도 파일에 원자적으로 저장한다.
작업별 OS 잠금으로 같은 자료의 동시 업데이트를 막는다. 부모가 종료되어도 이미 시작한
유한 작업의 결과는 보존하며, 재개 시 저장된 후보를 먼저 복원한다. 후보 저장 직후 부모나
worker가 중단되어도 같은 업데이트를 다시 적용하지 않는다. 불완전한 파일은 보존하고
완료된 후보로 간주하지 않는다.

기존 동기 경로에서 생성한 후보도 원본 정책 버전·학습 manifest·후보 가중치를 확인한 뒤
복원할 수 있다. 코드나 평가 계약이 바뀌면 이전 평가는 기록으로 보존하고 새로운 동일
조건 비교를 수집한다. 원본 평가와 후보 평가는 서로 다른 실제 세션이다.

## 자원과 관측

Windows worker는 `CREATE_NO_WINDOW`와 `BELOW_NORMAL_PRIORITY_CLASS`를 사용하고,
PyTorch CPU 스레드는 1개로 제한한다. 장치는 작업 요청의 CPU/CUDA 설정을 따른다.
운영체제의 낮은 CPU 우선순위가 GPU·게임·캡처 간 경쟁까지 제거한다고 가정하지 않는다.
worker는 별도 실행 로그와 작업 상태를 남기며, 실제 최적화 시작·종료와 수집 구간 시각을
기록한다. 프로세스가 동시에 존재한다는 사실만으로 전투와 학습이 실제로 중첩됐다고
보고하지 않는다.
첫 행동 callback은 비동기 기록 thread에서 실행하며 입력 제어 thread를 대기시키지 않는다.
설정 화면에서 신규 PPO가 먼저 끝나는 것을 막지만, 전투 즉시 중단·worker 준비 지연까지
없애지는 못하므로 실제 전투 송신 구간과 optimizer 작업 구간의 겹친 시간을 별도로 기록한다.

사용자 STOP, 작업 실패, 작업 시간 한도는 학습 쪽에서도 처리한다. PID 숫자만 믿고
다른 프로세스를 종료하지 않는다. 학습 실패가 발생해도 미검증 후보로 게임을 계속하지
않으며, 진행 중인 평가의 입력 안전 경계와 기록을 지킨다.

## 검증 기준

- 원본 평가가 학습 시작과 결과 대기 사이에 실행되는지 확인한다.
- 첫 전투 송신 기록 전에는 신규 PPO가 시작하지 않고, gate 대기 중 STOP도 처리되는지 확인한다.
- 후보 검증 전 후보 평가나 모델 교체가 없는지 확인한다.
- 부모/worker 중단과 후보 저장 직후 재개에서 중복 업데이트가 없는지 확인한다.
- 평가 자료·다른 정책 버전·변경된 manifest를 학습에 넣지 못하는지 확인한다.
- 숨김 실행, 별도 로그, CPU 스레드 제한과 실제 게임 중 추론 지연을 각각 확인한다.
- 실전 중첩과 수집 속도 변화는 실제 실행 증거로 보고하며, 단위검사 통과를 성능 개선으로
  대신하지 않는다.
