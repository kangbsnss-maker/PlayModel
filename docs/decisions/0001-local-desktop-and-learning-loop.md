# ADR 0001 — 로컬 데스크톱과 단계적 학습

날짜2026-09-26. 상태: **설계 채택, 기능 구현 전**.

## 맥락

제공 자료는 단일 과제에서 교정으로 개선되는 CNN·GRU 로컬 정책을 제안한다. 사용자는 이를 프로그램 프로젝트로 준비하고 나중에 장르별 플레이/유튜브 제작으로 확장하려 한다. 현재 게임은 미선택이며 GPU는 GTX1660 SUPER6144MiB다.

## 결정

1. Python `playmodel`을 공통 core로 두고 PySide6 desktop shell을 첫 GUI 후보로 채택한다. 현재 준비 CLI와 GUI는 같은 계약을 사용한다. 학습/추론은 GUI 밖 프로세스다.
2. 화면 단독 frozen-CNN BC→순환 BC 비교→검토된 누적 교정의 순서로 진행한다. PPO/자가대전은 환경·보상·출처 계약을 통과한 뒤 별도 채택한다.
3. 장르/게임 adapter와 정책을 분리한다. 새 게임은 새 프로필·행동 schema·자료·평가를 갖는다. 범용 전이를 기본 성과로 주장하지 않는다.
4. runtime dependency를 단계별로 설치한다. 준비 core는 stdlib/Python3.11+, 기준 개발환경은 이미 설치된3.12.13. GPU 라이브러리는 실제 CUDA 실행 확인 후 고정한다.

## 대안과 이유

웹 UI는 원격 접속이 필수일 때 다시 검토한다. 지금은 서버/브라우저 통신 계층을 추가할 이득이 작다. Electron/Tauri는 UI/런타임 언어·배포 작업을 늘린다. 대형 VLA/LLM 또는 영상만으로 VPT 재현은 첫 과제 검증에 필요한 데이터·자원을 넘긴다. PySide6가 이미 구현되었다는 뜻은 아니다.

## 결과와 재검토 조건

작은 모델/한 게임을 빨리 평가하고 로컬 도구를 재사용할 수 있다. Qt 패키징·라이선스와 IPC/watchdog 구현 비용은 남는다. 원격 관찰/멀티사용자 요구, 장기 계획 병목, 장르 전이 실험의 실제 이득이 확인되면 ADR을 갱신한다. [아키텍처](../architecture.md), [출처](../research/sources.md).
