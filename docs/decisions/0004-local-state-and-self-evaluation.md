# ADR 0004 — 로컬 상태 해석과 독립적인 자체 평가

날짜: 2026-09-27. 상태: 채택한 설계 방향. 구현·성능 검증은 후속 단계.

## 배경

사용자는 GPT/API 토큰 과금 없이 게임을 배우고, 스스로 플레이한 결과를 검토하며, 능력치 변화와 화면 문구도 처리하는 프로그램을 원한다. 기존 CNN+GRU 기준선은 저수준 행동 실험으로 유지한다. 최신 Pluto 공개 범위와 BWAPI·로컬 OCR의 근거, 확인하지 못한 사항은 [검토 문서](../research/pluto-and-state-review.md)에 기록했다. Pluto 전체 학습 소스를 사용할 수 있다는 가정은 하지 않는다.

## 결정

1. **제품 전체 경로는 로컬이다.** 실행·학습·평가에 외부 GPT, API 키, 유료 토큰 서비스, 클라우드 OCR, 외부 LLM judge를 요구하지 않는다. 개발 검토에 사용하는 Astra와 제품 의존성을 구분한다. 설치 파일·가중치 확보 후 네트워크 차단 시험으로 검증한다.
2. **정보 조건을 명시한다.** `screen_only`와 `api_assisted`는 별도 실험군이다. API 정답을 화면 정책 평가에만 쓰는 경우에도 정책 입력·훈련 데이터로 유출되지 않도록 분리한다. 관측 권한과 가려진 정보를 게임별로 정의한다.
3. **상태를 근거와 함께 보존한다.** HUD/OCR 관측은 ROI·원본 프레임·관찰/가용 시각·추출기 버전·신뢰도·만료 상태를 갖는다. 수치 변화와 원인은 별도 이벤트다. 기본 능력치·장비·레벨·버프·반올림을 게임별 규칙으로 구분하며 불명확하면 보류한다.
4. **읽은 글과 이해한 상태를 구분한다.** 게임별 스키마·템플릿·상태기계부터 시작하고 필요에 따라 학습된 의미 인코더·목표 기억·상위 계획기를 추가한다. 더 넓은 언어 모델도 로컬 후보일 뿐 필수 전제가 아니다. 이 구성요소를 하나의 거대 모델로 묶어야 한다고 가정하지 않는다.
5. **메뉴 능력은 따로 선언한다.** 사람이 연 메뉴의 관찰과 정책의 메뉴 열기·조작은 다른 capability다. 후자는 게임 소유 인벤토리·스탯·퀘스트 메뉴를 명시적 UI mode/action spec으로 허용한 뒤 구현한다. 일반 행동 정책은 리셋·계정·시스템·결제 메뉴를 다루지 않는다. 기존 단일 writer와 사람 우선권은 유지한다.
6. **평가기는 정책의 자기 확신을 정답으로 쓰지 않는다.** 캐릭터 성장과 정책 실력을 분리한다. 고정된 독립 결과·사람 라벨로 평가기 정확도를 먼저 검증하고, 불확실한 OCR은 재학습에서 격리한다. 자기 출력은 자동 BC 정답이 아니다. 자기 대전은 가능한 게임에서 별도로 검토한다.

## 결과와 승인 조건

향후 모듈은 관찰/인식, 상태·이벤트, 의미·기억, 행동 정책, 평가·학습 큐로 책임을 나눈다. 원본 사건을 유지하고 스키마·라벨·평가기·모델 버전을 연결한다. 공통 인터페이스를 공유해도 게임별 의미와 가중치의 재사용 성능은 각각 확인한다.

첫 게임이 정해지면 검토 문서의 L0–L5 시험을 프로필에 구체화한다. 숫자·부정/조건 문구·무변화·버프 만료·미리보기 등 실패 사례, 평가기 오탐/미탐/보류율, 기준 정책 대비 holdout 회귀, 동시 실행 자원·지연을 포함한다. 임계값은 후보 결과를 보기 전에 정한다. 네트워크 차단 경로, 상태 판정, 평가기 신뢰도가 통과하기 전에는 자율 재학습·모델 교체를 승인하지 않는다.

호스트 6144 MiB VRAM만으로 확장 모델의 정확도·속도·학습 가능성을 보장하지 않는다. 게임·언어·정보 입력 조건·성공 기준이 다음 구현 결정이다. 이번 ADR은 프로그램을 구현했다고 보고하는 근거가 아니다.
