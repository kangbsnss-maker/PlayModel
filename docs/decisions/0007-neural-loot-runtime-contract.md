# ADR 0007 — 신경망 전리품 선택과 런타임 계약

2026-09-27. 전리품의 획득·재활용을 신경망이 표본추출한 행동으로 기록한다. 가중치 해시와 행동 의미의 버전을 분리한다.

## 결정

- 기존 후보 출력과 `candidate_dim=16`, `context_dim=64`, 5개 phase embedding을 사용한다. 체크포인트 텐서 모양과 `policy_version()`의 가중치 해시는 바꾸지 않는다. 이번 변경만으로 기존 가중치를 재학습하거나 덮어쓰지 않는다.
- phase 1은 성장 선택과 전리품 선택을 포함한다. 새 `phase_schema`는 `combat0_upgrade_or_loot1_weapon2_shop3_character4-v2`, `runtime_contract`는 `brotato-recurrent-context64-candidate16-neural-loot-v2`다. 후보 관측·행동 마스크·실제 적용 증거는 각 선택을 구분해 보존한다.
- 전리품 카드 제목과 버튼의 원문 관측이 독립된 두 화면에서 일치해야 선택한다. 입력 후에도 독립된 두 관측으로 다음 메뉴 또는 다른 원문 제목의 전리품 카드를 확인한다. 같은 제목의 카드가 연속되면 픽셀 변화만으로 적용 성공을 추정하지 않는다. pending을 유지하며 정해진 확인 횟수 안에 증명되지 않으면 중단한다.
- 획득·재활용 매크로 자체의 보상은 0이다. 입력 적용 확인을 아이템 효과 확인이나 좋은 선택으로 취급하지 않는다. 효과는 `unknown`이며 별도의 능력치 재관측이 필요하다. 이후 독립적으로 확인한 전투·게임 결과를 원래 시간 순서에 연결한다.
- 옛 phase/런타임 자료는 원본 그대로 보존한다. 파일에 런타임 태그가 없으면 로더가 메모리에서 명시적으로 legacy로 분류한다. `load_full_run(..., require_training=False)`로 검토할 수 있지만 현재 계약의 PPO 입력으로 재사용하지 않는다. 신형 배치의 기본값으로 옛 파일을 자동 재분류하지 않는다.
- 이미 저장된 옛 후보와 그 학습 manifest는 새 비교의 출처로 사용할 수 있다. 이 경우 옛 학습을 다시 실행하지 않는다. 옛 학습만 있고 저장된 후보가 없으면 현재 런타임에서 그 학습을 재실행하지 않고 중단한다.
- 평가에는 `evaluation_scope_id`, phase/런타임 계약, `runtime_source_hashes`를 함께 기록한다. 의미 또는 코드 해시가 달라지면 이전 평가와 pending 작업을 제외 기록에 보존하고 새 scope를 만든다. source와 candidate를 모두 동일한 새 런타임에서 새 게임으로 평가한다. 옛 평가 점수와 섞지 않는다.
- 코드 해시는 메뉴·전투·초점 복구·상태 특징과 full-run 결합·PPO·계약·실행 조정기를 포함한다. 수집기 시작 뒤 해당 소스가 바뀌면 다음 수집 진입을 거부한다.

## 저장된 세션 재개

기존 `--resume <session-state.json>` 경로가 자동 이행한다. 상태 JSON을 직접 고치거나 체크포인트를 새 형식으로 저장할 필요가 없다. 저장된 `character_slot`, `weapon`, `evaluation_runs`와 같은 인수를 사용한다. `--resume-latest`도 지원하지만 여러 세션이 있으면 명시 경로로 재개 대상을 고정한다.

저장된 후보가 있으면 새 평가부터 시작한다. `--continuous`에서는 양쪽 평가가 완료된 뒤 후보를 다음 실험의 시작 가중치로 삼고, 새 계약에서 새 학습 게임을 수집한다. `--cycles 1`만 사용하면 이번 비교 후 멈춘다. 어느 경로도 후보를 자동 배포 승인하거나 실력 향상을 확정하지 않는다.

## 검증 범위

합성 검사에서 legacy 읽기·PPO 차단, 저장된 후보의 재학습 방지, 양쪽 신규 평가, 이전 pending 보존, 계약 불일치 평가의 제외를 검증한다. 실제 전리품 선택 성공과 게임 실력 개선은 별도 실행 증거가 필요하다.
