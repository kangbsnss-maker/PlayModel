## 필요한 구조

1. **관측과 사건 기록**: 객체 ID, 종류, 위치, 이동, HP 관측, 신뢰도, 시각, 원본 프레임.
   적 HP 바가 보이면 원본 해상도 crop으로 비율을 추적한다. 보이지 않으면 실제 HP를
   안다고 쓰지 않고 잔여 처치시간/필요 타격 수 추정과 불확실성을 따로 학습한다.
   객체 소실은 화면 이탈·가림·처치 가능성을 구분한다. 색상만으로 보석 획득을 확정하지 않는다.
2. **빠른 회피 경로**: 최신 객체 이동과 플레이어 이동을 이용해 충돌 위험을 예측하고
   전략 추론을 기다리지 않고 이동 후보를 제공한다. 유효 타격 영역·분류 정확도와
   관측부터 전송까지 지연을 측정한다. 상위 전략과 입력 writer를 따로 만들지 않는다.
   단일 중재자가 우선순위·유효기간을 확인해 실제 입력 하나를 정한다.
3. **전투 목표 정책**: 객체 집합과 시간 기억으로 공격 대상·수집·거리 유지·경계 복귀의
   가치를 학습한다. 전체 화면 축소만으로 작은 투사체와 HP를 해결했다고 가정하지 않는다.
   화면 경계와 실제 이동 가능 영역은 별도 상태로 추정한다.
4. **전투 요약과 경제 정책**: 적 종류/웨이브/빌드/난이도별 유효 공격 기회, 처치시간,
   피격, 수집, 생존 기록을 상점에 전달한다. 후보 구매 후 기대 화력·생존·수입·시너지와
   비용을 비교한다. 플레이 접근 실패와 무기 화력 부족, 웨이브가 강해진 효과를 구분한다.
   웨이브를 넘는 기록과 가치 추정으로 이전 구매에도 신용을 배분한다. 단순 전후 차이를
   아이템의 인과 효과라고 단정하지 않는다.
5. **UI 전이 그래프**: 선택 상태를 노드, 실제 키 입력 후 확인된 전이를 간선으로 저장.
   키 횟수뿐 아니라 걸린 시간·실패/재시도 비용으로 경로 선택. 사용자 제보인
   `danger_0 --left--> danger_6`는 출처 있는 초기 가설로 넣고 실제 선택 변화로 검증한다.
   구매 후보를 고르는 판단과 그 후보까지 이동하는 경로는 별도이며 확인 입력 전 재관측한다.

## 학습과 검증 순서

관측 정확도/사건 신뢰도 → 회피·수집·UI 개별 과제 → 전투-상점 장기 연결 → 고정 평가.
메뉴에는 이동 수/소요시간, 회피에는 위험 노출 대비 피격, 수집에는 기회 대비 확인된 획득,
공격에는 같은 조건의 처치시간, 구매에는 고정된 평가 조건의 이후 성과를 사용한다.
자기 추정값을 정답이나 성공 보상으로 반복 주입하지 않는다. 불확실한 사건은 원본과 함께
보존하되 해당 보상 학습에서 제외한다. 사람의 교정 이유는 출처 있는 별도 기록으로 연결한다.

레이어 수나 반복 판 수만 늘려도 이 연결이 자동으로 완성되지는 않는다. 게임 공통
객체/사건/기억/가치 구조와 게임별 인식·UI 어댑터를 분리하되, 전이 학습 성능은 이후
게임의 독립 평가에서 확인한다. 모든 제안의 제품 실행 경로는 로컬이다.
