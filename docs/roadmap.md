# 개발 로드맵과 수락 기준

2026-09-27. 일정 추정 대신 **통과 증거**로 다음 단계를 연다. M0 보존·저장소 준비를 마쳤고 Brotato 설치 진단·실제 client 캡처를 확인했다. M1–M2 전체 연결, 정책 학습, 자율 플레이는 아직 완료하지 않았다. 원안의 G0–G5/T01–T16은 [보존 기록](research/page-notes.md#page-19)에 남겨 두었으며 아래 M번호와 같은 완료 상태가 아니다.

2026-09-27 범위 보완: 능력치·텍스트·목표 기억과 자체평가를 아래 S1–S4로 추가했다. 텍스트/성장 상태가 첫 과제의 성공을 좌우하면 M3–M4 완료 전에 해당 검증도 충족해야 한다. 단순 조작 기준선의 성공을 전체 기능 완성으로 바꾸지 않는다. [보완 근거](research/pluto-and-state-review.md).

확정 목표는 **Windows Steam Brotato의 캐릭터 선택부터 이동·성장·상점·결과·재시작까지 전체 자동 플레이**다. 사람 시연·교정은 선택 사항이다. [Brotato 계획](games/brotato.md), [현재 실행 안내](guides/first-survivor-session.md), [빌드 학습 설계](guides/survivor-card-learning.md)를 따른다. 중국어 캐릭터 호버·특성 인식·시작 경로가 현재 연결 작업이며 해금은 부목표다.

## M0 — 연구·저장소 준비

산출물:29쪽 시각 분석/해시·페이지 대응, 아키텍처/ADR, 단계별 체크, GitHub용 로컬 패키지, 준비 CLI, 데이터/모델/영상 제외 규칙. 학습 환경 설치나 게임 연결은 포함하지 않는다.

수락: 모든 원본이 상세 메모/manifest에 대응하고 로컬 링크·패키지·준비 동작 검증이 통과한다. 원본 삭제는 이 보존/준비 검증 후 사용자 요청에 따라 root가 수행하고 정확한 hash 목록/완료 영수증을 남긴다. 전후 증거는 `scripts/verify_preparation.py`와 프로젝트 작업 gate로 관리한다.

## M1 — 첫 게임과 반복 과제 계약

입력: 확정된 Brotato/Windows Steam과 실제 설치 빌드, 중국어 UI, 창·캡처·입력 방식. 조준·접근성·해금·DLC·모드·난이도는 로컬 근거로 확인하며 설치 존재만으로 설정을 확정하지 않는다.

구현: 비공개 환경 프로필에 빌드·캡처·허용 입력, 전체 메뉴/웨이브 상태, 정상 결과 후 재시작, 성공·사망·중단 판정, 최대 길이, 선택적 인수, 저장/영상 범위를 기록한다. 현재 재시작이 미구현이면 미구현으로 표시하며 수동 재시작을 전체 자동 완료로 인정하지 않는다.

캐릭터 호버, 선택·시작 설정, 보상·강화·상점·결과 UI를 명시적 mode/action spec으로 시험한다. 호버 원문·캐릭터 ID·특성·해금 조건은 출처와 함께 기록한다. 조건 진행 추정과 실제 해금 상태 확인을 구분하며 계정·구매·저장 초기화는 자율 플레이에서 제외한다.

수락:

- 합성 환경에서 같은 계약으로 관측/입력/종료를 표현하고 미래 프레임·누락·잘못된 축을 거부한다.
- Brotato의 허용 입력으로 관측→전송→해제와 정상 재시작을 최소10회 반복 점검한다. 이10회는 초기 연결 점검 제안이며 학습 성능 표본 수가 아니다.
- 캐릭터 호버 뒤 이름·특성·잠금 여부·해금 조건의 증거를 연결하고, 선택→시작 조건→첫 웨이브 진입을 새 관측으로 확인한다. OCR·개발자 보정을 정책 가중치 학습으로 보고하지 않는다.
- 캡처/입력 지연 분포, 수신확인 가능 여부, reset 성공/실패 이유를 기록한다. 적용 확인 불가를 unknown으로 유지한다.
- 게임 내부 상태를 보상/진단에 쓰면 화면 정책 입력에서 제외했음을 확인한다.

막히면: adapter를 교체하거나 더 짧고 reset 가능한 과제로 좁힌다. 호환성 실패를 모델 크기 증가로 해결하려 하지 않는다.

## M2 — 기록·조작권과 최소 데스크톱 앱

선행: M1 계약. 구현: capture/input adapters, 전체 실행 조정자, 별도 정책 제안 프로세스(처음에는 규칙 기준선), 단일 writer/epoch/기한/watchdog, append-only events·영상·PTS, 인수 전후 버퍼. PySide6 실행·검토 화면은 이 경로에 연결하며 GUI나 시연을 실제 연결의 선행 조건으로 두지 않는다.

수락:

- 연속30분 파일럿(제안)에서 실제 저장률·프레임 누락·p50/p95/p99 관측/전송 지연을 기록하고 손실 구간이 식별된다.
- T01–06/T09–11에 대응하는 현재 행동 누출, 미래 관측, 짧은 탭, 버튼 유지 중 인수, 명시 반환, reset/단절, 겹친 보존, 디스크 부족/인코더 정지 시험을 통과한다.
- 추론 응답을 일부러 늦춰 사람이 인수한 뒤 이전 epoch가 입력하지 않는지 확인한다. GUI 정지·추론 예외·입력 장치 해제를 주입하고 지정된 추가입력 차단이 동작한다.
- 시스템 전체 중지와 정상 인수의 최종 버튼 상태가 규격과 맞다. watchdog값이 설정되어 있다는 사실 대신 실제 전송 로그로 확인한다.
- 시연/교정/평가 보호 파일과 사용 중 파일을 저장 청소기가 지우지 않는다. 앱이 종료되어도 partial 상태가 검토 없이 학습으로 들어가지 않는다.
- AI 이동→한 웨이브→보상/강화→상점→다음 웨이브를 연결한 뒤 전체 판·결과·재시작으로 넓힌다. 정상 경로에서 사람이 대신 이동·선택해야 하면 전체 자동 완료가 아니다.

수치 확정: 여기서10Hz/250ms와 원안30Hz를 측정해 바꾼다. 허용 지연/관측 나이/해제 기한은 게임 특성을 근거로 정하고 프로필 버전으로 동결한다.

## M3 — 자율 실행 기준선과 검토된 데이터

선행: M2 품질. 구현: 명시된 초기 이동/빌드 규칙 정책, 캐릭터·능력치·해금 조건의 관측 지식, 타임라인 검토, 판·원본별 그룹 분할, immutable dataset manifest, 정렬 검증. 사람 자료가 있을 때 단순 BC를 선택하며 사람 시연 확보를 필수로 요구하지 않는다. AI 실행 입력은 출처를 유지하고 자동 BC 정답으로 바꾸지 않는다.

수락:

- 작은 알려진 시퀀스에서 입력/관측/결과 이력과 후보 mask를 확인한다. 지도학습을 선택하면 라벨 출처와 zero-mask 분모, 소량 과적합을 검사하되 일반화 성능으로 보고하지 않는다.
- train/validation/test 원본 그룹 중복0, 파생 영상/같은 출처를 일부러 섞었을 때 거부. 프레임 수 대신 독립 세션·에피소드·라벨 시간·행동 분포를 보고한다.
- 신경망을 채택할 때 ML 환경의 GPU forward/backward, 실제 형상, peak VRAM, batch1 처리량, checkpoint 재로드 결과를 기록하고 lock한다. 실패 시 작은/frozen 모델부터 다시 측정한다.
- 규칙 기준선이 사람 없이 시작부터 결과·재시작까지 진행하는지 확인한다. 규칙으로 연결된 경로와 학습된 부분을 따로 보고하고 동일 조건의 비교 기준으로 보존한다.

실험 산출물: policy/rules bundle, 고정 dataset ID/설정/seed, 실행 로그, held-out 평가표, 실패 영상. 학습을 실행했다면 별도 가중치와 학습 로그를 첨부한다. 원문 지식 저장이나 사전학습 모델 다운로드를 정책 학습 완료로 세지 않는다.

## M4 — 로컬 학습·시간 기억과 고정 비교

선행: M3 기준선과 검증된 관측/결과. 구현: 상태·후보 점수기 또는 CNN·GRU 후보, burn-in/마스크·실제 입력 기억, 후보 평가/승격/롤백. 사람 인수 자료가 있으면 검토 후 BC/교정에 사용할 수 있다. 자율 시행으로 배우는 RL은 M6의 추가 조건을 충족하며, 사람 교정 부재를 자동화 중단 사유로 삼지 않는다.

비교는 규칙 기준선 대비 실제 과제 성과와 E01(화면 단독vs순환)부터 한다. 사람 자료를 쓰는 실험에만 E02(같은 사람 자료 예산의 기본 BCvs누적 교정)를 적용한다. 추가 자료량 효과와 방문 상태에 맞춘 교정 효과를 구분한다. 빌드와 이동 개선은 각각 고정한 비교 및 통합 비교로 나눈다.

첫 실험 계획 제안: candidate/baseline별30개 이상 평가 시작 회차, 가능하면 학습seed3개. 이는 검정력 보장 수치가 아니다. 초기 변동이 크면 표본수를 늘리거나 과제를 좁힌다. 후보 전후 같은 시작 목록/seed·시간제한을 사용한다.

후보를 실행하기 전에 evaluation protocol에 다음을 고정한다:

| 항목 | 정할 내용 |
|---|---|
| 주요 개선 | 성공률 최소개선 `δ_success` 또는 개입/분·사람시간% 최대값 `H_max`; 어떤 지표로 통과할지 미리 선택 |
| 절대 유용성 | 기본 성공률 하한 `S_min`; 쉬운 기준선보다 나아야 함 |
| 퇴행 | 기존 기본 과제 허용 하락 `Δ_max` |
| 실행 | 지연p95/p99·관측나이·누락·중지 경로 상한 |
| 증거 | 회차 분모·중단·불확실성, 시드/시작 조건, 분석 방식 |

`S_min/δ/Δ/H` 숫자는 게임 기준선 측정 후 정한다. 후보 결과를 보고 통과선을 바꾸지 않는다. 자율 평가는 개입 성공을 성공으로 세지 않는다. 보조 사람 참여 평가는 개입 횟수와 조작 시간을 둘 다 보고한다.

**프로젝트 첫 학습 완료:** 사전 기준을 만족하는 개선, 기존 과제 유지, 분할/시간/실행 품질 통과, 에피소드 경계 model bundle 교체와 롤백 재현. 신뢰구간이 너무 넓으면 성공 주장을 보류하고 추가 평가한다. T07/T08/T13/T15 완료 증거를 연결한다.

## M5 — 저장 최적화와 첫 영상 제작

영상 촬영 파일럿은 M2부터 시작할 수 있다. M5의 평가 비교 영상은 M4 증거가 있을 때 완성한다. 초기10시간 이하 수집으로 용량/화질을 측정하고 보존 예산을 확정한다.1000시간 가정으로 먼저 수집하지 않는다.

구현: 학습 데이터 보호/캐시 청소/정상 표본, 코드와 독립 고화질 촬영, 세션↔영상 시간 매핑, marker/편집 목록, 지표 오버레이/해설용 근거 export. 압축 E04/보존 E05는 같은 학습/평가 예산으로 비교한다.

수락:

- 화질/선별 후 작은 HUD·공격 예고·탭이 손실되지 않는지 기준 영상과 비교하고 M4 성과 허용 범위를 유지한다. 저장GB/h와 유효 학습시간 비율을 함께 보고한다.
- 보호/편집 pin/사용 중 참조를 건드리지 않고 cleanup dry-run 목록을 검토할 수 있다.
- OBS 등 고화질 원본과 사건 로그의 시작/종료 동기점 오차를 측정한다. 처음 제안 기준은1 source frame 이내지만 장치 경로를 측정한 뒤 실제 허용치/불확실성을 명시한다.
- 대표 실패→교정→같은 조건 비교 영상1편을 로컬 파일로 완성하고 소리/자막/개입표시/모델버전/지표분모·개인정보를 검수한다. 하이라이트 선택으로 전체 성과를 왜곡하지 않는다.
- 게임별 게시/음원 정책 출처를 확인한다. 공개/업로드는 사용자 게시 지시와 계정/영상 검수 후 별도 단계다. 이번 준비 작업에서 업로드하지 않는다.

## M6 — 검증된 게임에서 선택적 RL/재생

선행: M3 자율 기준선, M4의 고정 평가 계약, 신뢰할 보상/종료/최종 관측, 반복 reset, 새 정책 자율 수집. 조건이 부족하면 관측·제어·평가를 보완하며 가짜 보상으로 훈련했다고 보고하지 않는다. 사람 시연/교정은 필수 선행이 아니다.

구현/수락: reward와 실제 성공 상관·편법 탐지, current-policy/log-prob/수집버전, recurrent masking, 인수 궤적 격리와 종료/시간제한bootstrap 단위시험, E06 실제 성과 비교. T16과 중단률 보고 통과 전 운영 정책을 바꾸지 않는다.

재생 저장은 별도 옵션이다. 여러 초기 상태·긴 episode 반복에서 원본 관측 hash/결과/적용 시점 일치(T12)를 검증해야 하며 불일치는 영상 보관으로 돌아간다. 자가대전은 대전 양측 제어와 상대pool·고정 상대 평가가 있을 때만 추가한다.

## M7 — 두 번째 게임·장르

선행: 첫 게임의 M4와 실제 영상 제작 흐름. 새 게임은 새 M1 프로필/어댑터 계약·데이터·평가를 만든다. UI/기록 도구를 재사용하되 정책은 게임별로 시작한다.

수락: 공통 core를 새 게임 전용 조건문으로 오염시키지 않고 adapter/profile로 차이를 표현한다. 새 게임에서 학습/교정 효과를 따로 입증하고 첫 게임 회귀평가를 통과한다. 전이학습은 동일 예산 scratch대비 성과/데이터 효율을 측정해 이득이 있을 때만 채택한다. 장르별 영상 시리즈에도 game/task/model/dataset/eval 버전을 유지한다.

## S1–S4 — 상태 인식·의미·자체평가 확장

아래는 기능별 추가 수락 기준이며 이번 문서 작업에서 구현하거나 통과시킨 시험이 아니다. 상세 실험은 [ADR 0004](decisions/0004-local-state-and-self-evaluation.md)와 연결한다.

| 단계 | M단계 연결 | 구현과 검증 |
|---|---|---|
| S1 HUD/OCR | M1에서 필드 정의, M2에서 수집 | 숫자·문자·아이콘 정답을 갖춘 별도 클립셋. 숫자 exact-match/필드 정확도, 텍스트 CER, confidence별 오류·보류율, ROI miss·지연을 측정. 해상도·가림·폰트·애니메이션·미지 UI 대조 포함 |
| S2 상태·의미 | 첫 게임 의미가 필요한 M3 전 | 현재/최대/기본/장비/버프 값 분리. 레벨업/버프 만료/장비 교체/가격 비교의 양성·음성 사례. 단위·소수·자릿수/부정·수량·조건·순서 및 미지 문장을 평가. 증거 부족 시 unknown 유지 |
| S3 목표·자체평가 | M3 기준선부터 M4 비교 | 목표 상태·중단/복구 조건, 평가 결과의 사람 정답 대비 precision/recall·오탐/미탐·보류율. 동일 능력치에서 정책 비교와 캠페인 진행 비교 분리. 잘못 읽은 보상을 악용하는 사례와 미래 상태 누출 차단 |
| S4 로컬 통합 | 해당 기능 채택 전 | 캡처+OCR+상태+정책+기록의 전체 지연/peak VRAM·RAM 측정. 인식 주기를 줄였을 때 stale state와 놓친 사건 측정. 사전 파일 확보 후 외부 네트워크 차단 상태로 플레이/학습/평가 검증 |

성능 임계값은 첫 게임의 필수 정보와 기준선에서 정하고 후보 실행 전에 고정한다. 낮은 CER 하나로 퀘스트 의미 이해를 인정하지 않고, OCR 정확도 하나로 실제 과제 성과를 인정하지 않는다. 평가자 자신이 틀리는 비율을 먼저 측정한다. 새 언어모델/의미 인코더는 규칙 기준선 대비 필요성과 비용이 입증된 경우에 추가한다.

캐릭터 특성·해금 검증은 S1–S3에 포함한다. 한 캐릭터에서 다른 캐릭터로 호버할 때 원문 연결이 바뀌는지, 미해금 조건의 비교·수량·기간·난이도를 정확히 해석하는지, 진행 추정과 실제 선택 가능 전환을 구분하는지 확인한다. 해금 부목표가 주목표의 생존·진행 기준을 임의로 바꾸지 않도록 계획과 평가를 분리한다.

Pluto 실행 비교는 StarCraft/BWAPI가 실제 검토 대상으로 선택된 경우 별도 수행한다. 현재는 공개 자료 검토만 수행했으며 Pluto나 자체 모델을 실게임에서 실행한 성과는 없다. 화면 기반 경로와 구조 API 기반 경로의 결과를 같은 입력 조건으로 합치지 않는다.
